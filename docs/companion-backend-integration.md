# 小灰网站助手：现有博客前后端集成

`apps/server/my-blog` 的现有 Nest 进程已准备伴侣聊天模块及同源代理；`apps/blog-web/blog_web` 已接入小灰的实时 3D 陪伴层和聊天组件。小灰已部署到个人博客的正式服务器，使用博客原有数据库。

## 网站中的小灰

`StudyShell` 持久挂载 `src/components/companion/WebsiteCompanion.tsx`，切换首页和阅读页面不重建猫实例。运行时代码在同目录的 `runtime/`，模型、毛色贴图与聊天样式在 `public/companion/v1/`，资源约 11.4 MB，原 GLB 保持不变。

- 桌面在页面空闲后加载，手机宽度下先显示小爪印，点击后才下载模型。
- 轻点猫抚摸，长按约 550 ms 打开底部聊天输入条；键盘聚焦猫后 Enter 聊天、空格抚摸。平时没有常驻“聊聊”按钮。
- 阅读文章时自动切换安静陪读；收起偏好保存在本机。猫和召回入口避开网站右下的声音/视图按钮。
- 页面进入后台、打开设置等模态时，暂停绘制和交互、中止回复。卸载时取消加载并释放图形资源。遵守系统“减少动态效果”偏好。
- 在 3D 书房中，小灰挂到房间场景，使用房间相机、光照、遮挡和绘制时钟；点击空地行走，点击桌椅裸露面跳到预设安全落点。书本、日记、灯等原交互保留优先级，拖动镜头不触发走路。
- 房间导航按实际桌椅坐标规划，地面绕开家具；桌椅之间先回地面，避免跨越大段距离直接飞跃。默认低频散步（40–70 秒，可通过 `wanderInterval` 调整），阅读、隐藏、弹窗、后台或减少动态时不主动漫游。
- 阅读页及简洁模式使用角落陪伴层；同一个猫实例和聊天组件在两种视图间切换。房间内开放 `ground/chair/table/user` 移动能力，阅读层的 `moves` 仍为空，不把房间路径带到文章页。
- 聊天使用下面的现有博客接口。服务未启用时明确提示未连接，保留抚摸和本地姿态指令，不生成伪造的模型回复。

英语页面的猫控制入口已本地化，聊天界面和人格仍沿用小灰的中文版本。网站助手已接入当前公开文章解读、灯光与窗帘控制以及待确认的留言草稿；语音、全站知识检索和跨会话长期记忆尚未接入。

## 网站助手：阅读、房间和草稿

### 当前文章与选文解读

独立文章页和书架内页共同使用 `MagazineArticle.tsx`。组件向 `website-context.ts` 注册当前文章的 `slug / locale / title`，按真实 URL 校验活跃文章；翻页动画保留的旧页面不能继续提供上下文，切换文章时中止旧回答和旧计划。

日常操作无需新的常驻大按钮：打开文章后，长按小灰打开输入条，询问“这篇文章讲了什么”；需要解释某一段时，先在正文中选中文字，再长按小灰输入“解释这段”。选区在输入框取得焦点前捕获，最多 1000 个 JavaScript 字符单位，并可附所在小节标题。范围限于当前文章正文，不读取信纸、联系方式输入框或其他页面的文本。

浏览器不提交整篇正文，也不能提交任意网页 URL。后端通过现有 `PublicService.getArticleForCompanion`，按 `slug / locale` 从已发布文章库读取可信正文，不另行抓取网页，不接受浏览器标题覆盖真实标题。文章、选文及标题只作为待分析资料，不能授权猫咪动作、灯光操作或寄信；未能匹配原始 Markdown 的选文标记为用户提供的引用，而不是已核验原文。

正文上下文最多 16000 字符。长文默认取开头；选区能在后段正文精确定位时，提供开头与选区附近片段，总量仍受限。响应的 `context` 事件携带可信文章标题、路径信息和 `truncated` 标志；聊天记录展示“参考：文章标题”，部分正文会标注“部分正文”，模型也须披露没有读到全文。文章不可用时应明确说明，不能假装读过。此能力针对当前文章，不是全站自动检索或无限长文分析。

### 当前访客的房间控制

宿主只开放下列 7 种固定操作，不接受脚本、任意选择器或后台管理指令：

| 操作值 | 含义 | 本地口令示例 |
| --- | --- | --- |
| `ceiling_on` | 打开顶灯 | 开灯、打开顶灯 |
| `ceiling_off` | 关闭顶灯 | 关灯、关闭顶灯 |
| `lamp_on` | 打开台灯 | 打开台灯 |
| `lamp_off` | 关闭台灯 | 关闭台灯 |
| `lamp_auto` | 台灯恢复自动模式 | 台灯自动 |
| `curtains_open` | 拉开窗帘 | 拉开窗帘 |
| `curtains_close` | 合上窗帘 | 拉上窗帘 |

这些精确口令无需模型连接，也经过实时能力检查并使用现有房间状态和控制方法；只有本次操作确认成功才显示完成反馈。它们只影响当前访客的书房，不能修改网站全局配置。房间未就绪时能力列表为空，返回明确的不可用原因。否定、引用和文章中的命令不会作为精确本地口令执行。

### 留言与评论先成为草稿

用户明确要求起草时，模型可以提出 `{"kind":"draft","value":"letter","text":"纯文本草稿"}` 或 `comment` 步骤，正文最多 3000 字符。执行成功仅表示草稿已准备，不能声称已发送、发布或通过审核。

- `WebsiteDrafts` 只在有稿时显示轻提示“查看留言草稿”，不自动弹出信纸，不中断正在返回的动作回执。点击后先进入可编辑预览。
- 给博主写信：用户点击“继续写信”后打开现有 `LetterPaper`。昵称、邮箱由用户填写，公开展示选项默认不勾选，最终仍须用户点击“封缄寄出”。预览与信纸间保留用户修改；已有待审稿或手写未寄出的信不会被新稿静默覆盖。
- 待审稿的前端编辑状态只在浏览器内存保留，不放进 URL 或本地持久存储，刷新会丢失。用户在预览和信纸里的后续编辑、联系方式不自动回传给模型；模型已生成的原始草稿属于已有对话。寄送中或结果未知时保留原信纸与幂等提交包，先确认上次结果，避免重新生成编号造成重复寄送。肯定回执继续交给 `LetterDeliveryContext`，不把私密凭条交给模型。
- 文章评论沿用现有 Giscus。只有当前文章挂载了可用的评论入口才开放 `comment`；用户编辑后主动复制、定位评论区，并自行完成登录和提交。不会向 Giscus 自动填表、发送消息或绕过认证；没有配置时说明不可用，可选择给博主写信。

写信仍使用既有 `/api/v1/public/letters` → `/v1/public/letters` 通道，与伴侣聊天接口分开；现有校验、审核、限流和重试规则继续生效。准备草稿不会触发此 POST。

### 网站适配器与可迁移性

`WebsiteCompanion` 通过挂载参数 `website` 注入 `website-assistant.ts`。适配器聚合 `getCapabilities / getContext / subscribeContext / execute / prepareDraft`，分别连接本站文章上下文、房间设置和草稿界面；可迁移的猫运行时不自行遍历任意网站 DOM，也没有网站管理员凭据。未提供适配器时没有网站控制和草稿权限。迁入其他网站时，需要实现对应适配器；若复用 3D 房间，还需替换场景挂接与家具导航，不能照搬本站坐标。

## 路由与浏览器凭据

前端已使用 `apiBase: '/api/companion'`，保留传输层默认的 `credentials: 'same-origin'`。

| 用途 | 路径 |
| --- | --- |
| 浏览器同源接口 | `/api/companion/{endpoint}` |
| Nest 原生接口 | `/v1/public/companion/{endpoint}` |
| 现有后端监听地址 | `http://127.0.0.1:3000` |
| GET 端点 | `status` |
| POST 端点 | `sessions`、`chat`、`result`、`cancel`、`clear` |

Nest 使用 URI 版本控制，版本前缀为 `/v1`，没有全局 `/api` 前缀。`/api/companion/` 通过专用 Nginx 规则改写为 `/v1/public/companion/`；不经过 Next 的 `/api/study/` 路由，也不拼到现有 `NEXT_PUBLIC_API_URL` 的 `/v1/public` 后面。

生产访客身份由 HttpOnly、Secure、SameSite=Strict、Path=/ 的 `__Host-cat-agent` 签名 Cookie 表示。Cookie 随同源请求发送，代理保留 `Cookie` 与 `Set-Cookie`，不需要把博客管理员登录凭据发给聊天接口。`sessionId` 本身不构成访问许可；会话、取消、清空和动作回执都须归属于当前访客。

`chat` 响应是 `application/x-ndjson`，每行一个事件，并含心跳；不能作为 SSE 或单个 JSON 解析。代理直接转发流，不等待完整回复。

### 前端对接约定

1. `POST sessions` 发送 `{}`，取回 `sessionId`；浏览器自动保存签名 Cookie，不在 JavaScript 中读取它。
2. 每次 `POST chat` 生成新的 UUID `turnId`。必须传入当前页面实际支持的 `capabilities`，没有家具时 `moves` 为空；不能省略后继承旧书房的能力。可选的 `site` 和 `drafts` 分别列出当前房间控制和草稿类型；可选 `context.article` 只接受文章标识、标题及受限选文，`context.room` 仅包含本访客灯光与窗帘状态。
3. 逐行读取 `status`、`context`、`text`、`heartbeat`、`plan`、`error`、`done`。`context` 用于显示后端确认的文章来源。`done` 表示这次生成结束，**不表示动作执行成功或草稿已经发送**。
4. 收到 `plan` 后，客户端先验证本页能力和当前状态，再逐步执行。执行后用 `POST result` 回传同一个 `sessionId / turnId / planId` 和真实 `results`；后端不会直接操作页面或重复执行动作。
5. 中止回复/计划时发送 `POST cancel`，包含 `sessionId`、`turnId`。清空对话时发送 `POST clear`，包含 `sessionId`，然后丢弃本地会话 ID；这两项都不会重置额度。

例如固定在网页角落、只开放坐下和挥爪的小灰，可以发送：

```json
{
  "sessionId": "由 sessions 接口返回的 UUID",
  "turnId": "本轮新生成的 UUID",
  "message": "伸个爪给我看看",
  "state": { "mode": "room", "motion": "idle", "visible": true, "paused": false },
  "capabilities": { "actions": ["sit", "paw"], "moves": [], "modes": [], "repeat": false }
}
```

动作计划形如 `{"type":"plan","planId":"UUID","steps":[{"kind":"action","value":"paw"}]}`。回执的 `results` 是有序数组，每项形如 `{"index":0,"kind":"action","value":"paw","status":"succeeded"}`；状态只能为 `succeeded`、`blocked`、`cancelled`、`unknown`，可附不超过 240 字符的 `reason`，并传入执行后的 `state`。同一回执可幂等重发，修改已确认结果会返回 409。无法确认结果时应报告 `unknown`，不能重新执行来猜测是否成功。

请求为 JSON，整个正文上限 16000 字节，单条消息上限 2000 个 JavaScript 字符单位，一次计划最多 3 步。流式首包前错误使用 HTTP 状态和 JSON `code`；首包后使用 NDJSON `error` 事件。客户端需处理：

| 错误码 | 客户端行为 |
| --- | --- |
| `SESSION_EXPIRED`（404） | 创建新会话；仅尚未得到计划的本轮消息可重试一次，不重放旧动作 |
| `DUPLICATE_TURN`、`STALE_PLAN`、`RECEIPT_CONFLICT`（409） | 停止自动重试，不把旧计划当作新指令 |
| `RATE_LIMITED`、`SESSION_LIMIT`、`TURN_LIMIT`（429） | 遵守 `Retry-After`（如有），保持本地陪伴动作可用 |
| `COMPANION_DISABLED`、`COMPANION_UNAVAILABLE`、`NOT_CONFIGURED`（503） | 明确提示模型未连接，保留本地口令和宠物交互，不伪造聊天回复 |

协议同时支持猫咪动作、固定房间操作和准备草稿；语音、全站知识检索和跨会话长期记忆尚未接入。浏览器传回的结果仅用于对话反馈，不能作为网站业务操作的权限证明。`site` 步骤使用上述操作值，`draft` 步骤另外携带纯文本 `text`，其他步骤不接受附带文本。回执仍只有执行结果，不回传草稿正文或联系人信息。明确的本地口令（如“坐下”“走走”“来这里”“上桌子”“上椅子”“回地面”“打开台灯”“拉开窗帘”）先经过当前能力检查并在本机执行，不调用模型；自由聊天、文章解读和由模型起草文字继续使用后端。

## 本地联调

前端新增的 Next route 只在 `NODE_ENV=development` 且显式设置 `COMPANION_PREVIEW_API` 时启用。唯一允许的目标形式是 `http://127.0.0.1:<有效端口>`；未设置、目标非法或生产构建均返回 503。它不会自动连接公网或读取生产代理令牌。

在已经可以启动的博客开发环境中，向前端进程传入以下非秘密设置：

```powershell
$env:COMPANION_PREVIEW_API = 'http://127.0.0.1:3000'
pnpm dev:study
```

已有 `dev:study` 脚本将 Next 绑定在 `127.0.0.1:3100`。打开 `http://127.0.0.1:3100`。本地代理无法从 Next App Route 可靠取得原始 TCP 客户端地址，所以联调时必须保留回环地址绑定，不要改成 `0.0.0.0` 或用隧道公开这个开发入口。需要 3001 端口时，使用 `pnpm exec next dev --hostname 127.0.0.1 --port 3001`。

后端仍使用现有开发启动方式及 `.env.dev` 配置机制。伴侣模块须显式设置 `CAT_COMPANION_ENABLED=true`，并使用开发模式；如配置来源白名单，应包含实际打开的本地 origin（含端口），例如 `http://127.0.0.1:3100`。将后端 `.env.companion.example` 中需要的字段合入现有私密配置；示例文件本身不会被自动加载。

本地代理保留浏览器的本地 `Host`、原始 `Origin`、`Sec-Fetch-Site` 和 Cookie。所有客户端提交的 `X-Cat-*`、`Forwarded`、`X-Forwarded-*` 和 `Authorization` 都不会转发。写请求必须带完全匹配的本地 Origin，正文须为 JSON 且最多 16000 字节；来源不符或未知端点在访问后端前被拒绝。浏览器没有发送的写请求 Origin 不会被补造。

此设置只决定聊天接口联调通路，小灰的显示由网站组件独立控制。未配置模型时不能生成真实回复；接口连通、会话行为和模拟模型测试可独立验收。

文章解读还需要现有后端能读取已发布文章数据，不能只启动一个没有公共文章解析器的独立引擎来冒充本站解读。若需要在本地实际寄信，另按现有信纸机制设置前端 `LETTERS_PREVIEW_API=http://127.0.0.1:<邮箱后端端口>`；`COMPANION_PREVIEW_API` 不会代替这个设置。仅准备、查看和修改草稿不需要寄信接口可用。Giscus 是否显示仍由既有 `NEXT_PUBLIC_GISCUS_REPO / NEXT_PUBLIC_GISCUS_REPO_ID / NEXT_PUBLIC_GISCUS_CATEGORY_ID` 配置决定。

## 生产配置

现有后端继续由原来的服务管理器运行，仍只监听回环地址。不创建 `4318` 端口，不创建独立 companion 服务。伴侣模块默认关闭，缺少猫的配置不应阻止原有博客启动。启用后应由模块校验以下配置：

| 配置 | 要求 |
| --- | --- |
| `CAT_COMPANION_ENABLED` | 默认 `false`，显式设置 `true` 才初始化伴侣服务 |
| `CAT_AGENT_MODE` | 可省略，`NODE_ENV=prod/production` 自动启用生产保护；若显式配置，生产只能为 `production` |
| `CAT_AGENT_ALLOWED_ORIGINS` | 精确的 HTTPS origin，例如 `https://www.new-universe.cn`，无路径、末尾 `/` 或通配符 |
| `CAT_AGENT_COOKIE_SECRET` | 独立随机 Cookie 签名密钥，至少 32 字节 |
| `CAT_AGENT_PROXY_TOKEN` | 另一条独立随机令牌，至少 32 字节，与 Nginx 私密配置一致 |
| `CAT_AGENT_STATE_DIR` | 当前后端服务账号可写的持久绝对目录，不放在静态网站或版本发布目录内 |
| `CAT_AGENT_PROVIDER`、`CAT_AGENT_API_KEY`、`CAT_AGENT_MODEL`、`CAT_AGENT_BASE_URL`、`CAT_AGENT_TIMEOUT_MS` | 模型参数，仅在后端配置；完整字段和默认值以后端 `.env.companion.example` 为准 |

既有后端的 `start:prod` 使用 `NODE_ENV=prod`、配置模块读取 `.env.prod`；伴侣适配已将 `prod` 和 `production` 都视为生产。沿用已有后端配置注入方式，不创建额外的后端启动入口。Cookie 密钥、代理令牌、模型 key 不可复用，不进入 `NEXT_PUBLIC_*`、前端构建、日志或仓库。

模块未启用或无法初始化时，Nest 的 `GET status` 返回 `configured: false`，其他伴侣操作返回 503，原有博客模块继续工作。模型默认供应商为 DeepSeek，不隐式借用管理后台的 AI 密钥。

开发阶段使用的临时模型密钥应在正式发布前更换。这里只列配置字段，不能把聊天中曾提供的值、示例占位文字或开发配置直接当作生产凭据。

`ops/nginx-myblog.conf` 已包含局部 `/api/companion/` 规则：

- 改写到现有后端的 `/v1/public/companion/`，覆盖三条 `X-Cat-*` 可信代理头，清空 `Forwarded` 与 `X-Forwarded-For`。
- 原始 `Origin` 原样传递；仅 `GET` 没有 Origin 且 Host 为明确网站域名时，补充可信的 `X-Cat-Origin`。写请求不会得到补造的 Origin。
- `X-Cat-Client-IP` 使用 `$remote_addr`，不接受浏览器自报的 IP；不修改全站 `trust proxy`。
- 限制正文 16000 字节，关闭响应缓冲、代理缓存与 gzip，读取空闲超时 90 秒，以保留 NDJSON 心跳与流式反馈。
- 代理令牌默认空，猫接口返回 503。可选 include 使用通配符，私密文件不存在时不会让整份 Nginx 配置因缺文件而启动失败。

获准部署时，使用 `ops/nginx-companion-secret.conf.example` 创建私密文件 `/etc/nginx/snippets/myblog-companion-secret.conf`，只保留一个匹配的有效文件。填写与后端 `CAT_AGENT_PROXY_TOKEN` 相同的真实随机令牌；示例文件里的注释和占位文字不能作为生产凭据。该文件由 Nginx 管理员保管，不进入源码、网站目录或公共制品。

仓库中的 Nginx 基础模板监听 80 端口，不等于已配置 HTTPS。正式启用时需将这段规则合入实际对外 HTTPS 网站配置，并检查已有证书、重定向与站点 Host 设置。当前配置面向网站服务器上的本机 Nginx，不支持直接把 Vercel 当作可信代理。

如果 Nginx 前面还有 CDN 或负载均衡，`$remote_addr` 可能代表该代理，访客会共用其 IP 额度。只有明确验证可信代理地址范围及真实地址恢复方式后才能改变这个行为，不能直接信任公网提交的转发头。直连 API 域名或通用 `/api/v1/public/companion/` 路径不会得到可信代理令牌，不应绕过生产授权。

## 会话、额度和进程重启

当前实现只支持现有后端单实例。会话在内存中，后端重启后会话失效；客户端应识别 `SESSION_EXPIRED` 并创建新会话，不能自动重放旧动作或回执。每日请求额度写入持久账本，重启不能重置预算；并发限制在进程内维护。

持久目录使用独占锁。不要启用 PM2 cluster 或多副本，不要用 PM2 reload 的新旧进程重叠方式更新；若实际环境仍用 PM2，需要先 stop、确认旧进程退出，再 start。现有单实例 systemd 服务应完成正常停止、释放锁后启动。扩容需要另行设计共享会话与原子额度存储，本次没有进行 Redis 迁移。

若进程异常退出留下锁，只能在确认旧进程已停止且没有其他进程使用此目录后处理遗留锁；不要删除预算账本来恢复启动。
