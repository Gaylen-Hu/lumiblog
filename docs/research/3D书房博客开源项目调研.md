# 3D 书房博客参考项目调研与吸纳决策

调研日期：2026-11-04
关联文档：[沉浸式书房博客改版开发方案](../design-draft/沉浸式书房博客改版开发方案.md)

## 1. 结论与核验范围

建议组合吸纳不同项目的局部经验，在现有 Next.js 博客中增量实现，不整体迁移到某个模板。

- 内容与降级架构：优先参考 Qiuner。
- Next.js 与共享 Canvas：参考 pmndrs/react-three-next，并对照 jotyy 的实现。
- 命中区域、交互反馈与资产组织：参考 sooahs-room-folio。
- 昼夜烘焙混合与环境微动：参考 Bruno Simon。
- 稳定空间槽位与动态内容：参考 Oniria。
- 小物件触发 DOM 面板：补充参考 trevsm/3D-Portfolio。

本轮核验了仓库元数据、目录、README 和下文列出的关键源码，未安装运行这些项目，未真机测试其线上站点。因此性能、无障碍程度、移动端稳定性和生产可用性不能视为已验证。README 中的分数及体积不作为 LumiBlog 的性能承诺。

访问方式：按 agent-reach 技能尝试 GitHub CLI 与 Exa 后端；CLI 网络受限、Exa 包装器不可用，改用连接的 GitHub 工具读取公开仓库。agent-reach 命令缺失，无法完成版本更新检查。本轮没有复制第三方代码或下载其模型、纹理、音效。

## 3. 各项目的具体参考价值

### 3.1 jotyy/r3f-portfolio

- [仓库与说明](https://github.com/jotyy/r3f-portfolio)
- [持久 Layout](https://github.com/jotyy/r3f-portfolio/blob/main/src/components/dom/Layout.tsx)
- [Canvas 与 tunnel 输出](https://github.com/jotyy/r3f-portfolio/blob/main/src/components/canvas/Scene.tsx)
- [关联 DOM 的 View](https://github.com/jotyy/r3f-portfolio/blob/main/src/components/canvas/View.tsx)
- [依赖版本](https://github.com/jotyy/r3f-portfolio/blob/main/package.json)

已确认：Layout 固定显示 Scene，客户端动态加载 Canvas；Scene 渲染 tunnel 输出，View 跟踪 DOM 元素。README 说明 scissor 分割视口，这由其 View 方案配合完成，不能描述为项目自行实现了全部底层逻辑。

吸纳：房间在同一浏览会话内打开、关闭内容面板时不重复初始化；渲染与 DOM 分工明确。

不照搬：其 React 18、R3F 8、Next 14 依赖不能原样带入现有 React 19、Next 16 项目。Preload all 也不能直接用于完整房间资产，否则可能过早加载全部资源。单房间全屏展示无需为 scissor/tunnel 引入额外复杂度。

授权：仓库 API 未识别许可证，package.json 声明 MIT，但根目录本轮未发现独立许可证文本。复用实质代码前补核授权与版权来源；当前采纳架构思想。

### 3.2 andrewwoan/sooahs-room-folio

- [仓库与已知问题](https://github.com/andrewwoan/sooahs-room-folio)
- [场景、材质、动画和命中逻辑](https://github.com/andrewwoan/sooahs-room-folio/blob/main/src/main.js)
- [Shader](https://github.com/andrewwoan/sooahs-room-folio/tree/main/src/shaders)
- [Blender 文件](https://github.com/andrewwoan/sooahs-room-folio/tree/main/blender%20files)
- [MIT 许可证](https://github.com/andrewwoan/sooahs-room-folio/blob/main/LICENSE.md)

最值得吸纳的是作者记录的真实问题：对可视网格直接做悬停缩放，会让射线离开目标、动画恢复、又重新命中，形成抖动。源码使用静态 hitbox 与原物件的映射解决部分目标的问题，同时指出命中盒也可能挡住后方物件。

LumiBlog 应区分可视物件与命中区域，交互目标使用稳定 ID；合理控制大小、前后遮挡和点击优先级。对于会移动的抽屉或小猫，命中区域应随语义对象状态更新，不能所有物件都永远使用固定世界坐标盒。

材质上已有 day/night 纹理与 shader 混合，能够参考多时段烘焙组织。即使未创建运行时 Light，玻璃透射、shader、纹理与动画仍有成本。

授权：代码有 MIT 文本。README 单列商业材质、壁纸、音乐、音效等第三方来源，作者拥有某素材授权不等于授权随仓库转让；不直接搬用整套美术资源。

### 3.3 Qiuner/Qiuner.github.io

- [项目与架构概览](https://github.com/Qiuner/Qiuner.github.io)
- [内容独立于世界的 ADR](https://github.com/Qiuner/Qiuner.github.io/blob/main/docs/adr/0001-content-is-independent-of-worlds.zh-CN.md)
- [内容稳定 ID 类型](https://github.com/Qiuner/Qiuner.github.io/blob/main/src/content/types.ts)
- [静态 HTML 与 Canvas 宿主页](https://github.com/Qiuner/Qiuner.github.io/blob/main/src/pages/index.astro)

内容定义包含稳定 id，不包含场景坐标；视觉通过绑定引用内容。静态页面包含项目文字、链接与 noscript 说明，独立于 WebGL 入口脚本存在。README 还提出共享 Runtime 拥有渲染器、更新调度和资源生命周期；本轮未逐项审计该 Runtime 的完整实现。

吸纳方式：现有后端仍是内容事实来源，不再新增一套手工维护的 Content Kernel。前端增加轻量内容适配层和 RoomBinding，使用稳定分类/内容 ID 与 canonical URL，而非数组下标或网格名称对应文章。slug 变化时仍需遵循现有路由和重定向策略。

静态优先意味着服务端先输出能阅读的介绍、内容入口和链接，再渐进增强为房间。不能仅在 WebGL 失败后才依赖客户端临时生成降级页面。

不照搬：Astro/Vue、多世界、门户和完整 Runtime 架构对当前一间房过重。授权 API 未识别许可证，本轮根目录未发现独立许可文件；参考思想，不直接复用实质代码或资产。

### 3.4 miflow13/Oniria

- [项目说明与工程复盘](https://github.com/miflow13/Oniria)
- [空间槽位布局](https://github.com/miflow13/Oniria/blob/main/src/app/map/libraryRoomLayout.ts)
- [Sanity schema 目录](https://github.com/miflow13/Oniria/tree/main/src/sanity/schemaTypes)

README 描述 DEV 内容、Sanity 世界配置和 Three.js 表现的分离；物理槽位保持稳定，内容可以更换。布局源码定义了槽位 ID。作者还记录了封面过多导致渲染负担、数据到达重置镜头、巨型书架难导航、装饰导航增加理解成本等问题。

吸纳：固定数量的书架分类入口和预设镜头；内容刷新只更新列表，不重建房间或重置摄像机；近处需要时再加载封面。空分类可隐藏内容标签或提供正常空态，不出现不可用入口。

不照搬：六房间、自由行走、Sanity、话题活跃度演化与定时重排。它是实验性项目，不能以存在仓库推断这些机制已具备生产可靠性。当前不为 LumiBlog 增加第二个 CMS。

授权 API 未识别许可证，本轮根目录未发现独立许可文件。只参考结构与复盘结论。

### 3.5 brunosimon/my-room-in-3d

- [仓库](https://github.com/brunosimon/my-room-in-3d)
- [昼夜与中性烘焙混合](https://github.com/brunosimon/my-room-in-3d/blob/main/src/Experience/Baked.js)
- [咖啡蒸汽](https://github.com/brunosimon/my-room-in-3d/blob/main/src/Experience/CoffeeSteam.js)
- [Camera](https://github.com/brunosimon/my-room-in-3d/blob/main/src/Experience/Camera.js)
- [Experience 目录](https://github.com/brunosimon/my-room-in-3d/tree/main/src/Experience)

这是本次很有价值的工程补充。Baked.js 分别持有 day、night、neutral 和 light map，并通过 uniforms 调整混合与局部光色。CoffeeSteam.js 在有限几何上使用时间参数驱动 shader，展示小区域持续变化的实现方向。目录也实际分离了 Camera、Renderer、Resources、World 和不同局部效果。

吸纳：V1 资产预留中性光照与独立可调区域；V2 比较预设烘焙混合与轻量灯光方案；V1 微呼吸感只选少量区域，不让所有家具漂浮。咖啡蒸汽作为可选视觉细节，不增加 V1 必交范围。

不照搬：现有 Camera 中 20 度 FOV 与外部构图不适合直接作为屋内人眼视角；源码包含旧 Three.js API，需要依据当前版本重新实现。多套大纹理并存的显存成本必须测量。

授权 API 未识别许可证，本轮根目录未发现独立许可文件，暂作思想和视觉参考，不直接搬运模型、烘焙贴图或 shader。

### 3.7 新增：trevsm/3D-Portfolio

- [仓库](https://github.com/trevsm/3D-Portfolio)
- [Canvas 与 DOM Overlay](https://github.com/trevsm/3D-Portfolio/blob/main/src/App.js)
- [电脑物件点击与面板内容](https://github.com/trevsm/3D-Portfolio/blob/main/src/models/Computer.js)
- [许可证](https://github.com/trevsm/3D-Portfolio/blob/main/LICENSE)

App.js 将 Canvas 与 Overlay 分离，物件通过 setItems 打开内容；Computer.js 包含悬停、开合动画与 HTML 项目内容。另有 GPU 档位判断后选择是否启用后期效果的代码。

吸纳：物件只发送打开某类内容的事件，DOM 负责展示；统一面板容器管理关闭和恢复。GPU 检测可以提供初始建议，运行表现与用户偏好决定最终质量档位。

不照搬：正文直接写在模型组件中、固定 setTimeout 开放交互、无上限使用 window.devicePixelRatio，以及示例中的旧版 Canvas 参数。它是等距房间，视觉构图也不符合已经确认的屋内视角。

MIT 文本明确，第三方模型和图片仍需逐项核查。

## 4. 写入 LumiBlog 的实施决策

| 编号 | 纳入阶段 | 具体任务 | 验收证据 |
| --- | --- | --- | --- |
| REF-01 | V1-01、V1-05 | 内容适配层与 RoomBinding 分离，稳定 ID 引用 | 新增/排序内容不修改模型；内容刷新不重置镜头 |
| REF-02 | V1-06 | 服务端先输出可用 HTML，3D 渐进增强 | 禁用 JS、WebGL 失败时仍能通过链接阅读 |
| REF-03 | V1-04、V1-11 | 单 Canvas、单动画调度与 DOM 接管 | 同一房间打开/关闭内容不重复初始化；纯阅读页可暂停或释放场景 |
| REF-04 | V1-04、V1-07 | 稳定命中区域与可视动画分离 | 悬停不抖动；触屏可点中；后方物件不被不合理命中盒遮挡 |
| REF-05 | V1-03、V2 | 中性资产与可切换光照管线 | 夜晚、阴天、关灯不残留明显黄昏亮斑；纹理成本记录 |
| REF-06 | V1-10 | 少量局部 shader/程序微动 | 可暂停、可关闭；不牺牲交互帧率 |
| REF-07 | V1-07 | HTML 语义入口、焦点移交、键盘返回 | 完整键盘流程通过；a11y 库未采用也不影响交付 |
| REF-08 | V1-05 | 固定空间槽位与动态列表解耦 | 分类为空、增加文章、切换语言时场景稳定 |
| REF-09 | V1-03、V1-09 | 资产来源与授权台账 | 每个上线资产记录来源、许可、修改情况与署名要求 |

这些任务吸纳为现有交付项的实现约束，不另设只做研究的用户版本。按用户与助手协作逐阶段完成，不估算工期；参考项目不能代替实际实现与验收，也不因列出更多库而增加必需依赖。

### 不新增的强制依赖

- tunnel-rat / scissor：需要多 DOM 区域共享不同 3D 视口时再评估。
- @react-three/a11y：验证 React 19 与 R3F 版本兼容后再决定，HTML 焦点支持必须自己验收。
- GSAP：可选时间轴；始终只有一个镜头写入源。
- Sanity / Astro / 多世界 Runtime：不替换现有内容系统和 Next.js。

## 5. 美术资源获得的实际帮助

本轮找到的是可研究的资产管线与实现样例，不是可直接商用的整套书房资源包。

- sooah 有 Blender 文件及纹理组织，可研究命名、材质分组与模型导出；第三方商业材质不可假定可复用。
- Bruno 的日夜、中性烘焙组织可指导我们的资产规格，但没有据此获得其模型和贴图授权。
- trevsm 提供低复杂度、统一色系房间的参考，说明 V1 可通过统一风格控制资产成本。
- 小黑猫仍需独立落实简化程序角色或授权模型与动作；这些仓库未解决猫的完整资产来源。
- 正式复用代码前固定提交版本、保留版权文本；素材按独立授权逐项记录。
