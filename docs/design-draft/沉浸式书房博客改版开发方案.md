## 1. 项目定位

将博客首页改为一个可以轻度探索的个人书房。访客直接置身屋内，通过书架阅读文章、日记本浏览日常、抽屉里的信封联系博主，通过小黑猫发现隐藏内容。

房间承担个人表达和内容入口，文章正文继续采用适合阅读、搜索与分享的网页界面。

### 已确认的设计方向

- 屋内第一人称视角，画面铺满浏览器，不采用房间外壳、微缩平台或外围留白。
- 暖木色家具、柔和灯光、生活化细节；窗外可以随时间和天气变化。
- 交互提示克制，不常驻展示标签、热点圆点或明显描边。
- 主要内容只需少量探索即可发现；隐藏彩蛋可更深入。
- 抽屉里的红印章信封用于留言和联系；小黑猫用于隐藏彩蛋。
- 每个阶段均交付一个可以独立上线、供访客正常使用的版本。

## 2. 分期原则与上线底线

各阶段在上一阶段上增量发布。任何阶段结束后，都允许暂停后续开发，当前版本仍能长期正常运营。

### 每个版本必须满足

1. 文章、日常、关于、项目等已有内容仍可正常访问，保留原有有效 URL、多语言和分享能力。
2. 角落提供文字导航，访客不必完成探索才能访问主要内容。
3. 支持桌面与手机，加载失败或设备图形能力不足时自动提供可用页面。
4. 所有可点击功能均完整闭环，不出现无反馈按钮、开发中入口或提交后无人接收的表单。
5. 尚未开发的物件只作为装饰，不制造可操作的错误暗示。
6. 提供返回、关闭、加载和错误反馈；主要功能可通过键盘与文字导航完成。
7. 上线前完成本阶段验收，并可回退到上一版本。

### 任务管理约定

- 本文每个阶段内的任务为该版本的必要交付，阶段外的能力不阻塞当前版本上线。
- 技术原型、建模中间稿和内部演示是阶段内检查点，不作为面向用户的交付版本。
- 首期不引入自由行走、碰撞、物理模拟或多房间系统。
- 视觉资产、接口、后台和异常处理均计入对应功能，避免只交付动画外观。

## 3. 最终体验与物件规划

初始视角位于书桌附近，左侧书架、前方书桌与窗户清晰可见。避免椅背遮住日记本等主要入口。

| 物件 | 内容或功能 | 最终交互 | 首次交付 |
| --- | --- | --- | --- |
| 书架 | 文章、专栏 | 靠近书架，展开分类和文章列表 | V1 |
| 日记本 | 日常、时间线 | 镜头靠近，展开日常内容 | V1 |
| 墙上照片 | 关于我 | 展开个人介绍 | V1 |
| 笔记本电脑 | 项目、作品 | 屏幕亮起并展示项目 | V1 |
| 台灯 | 室内照明 | 手动开关，与环境光配合 | V2 |
| 窗户 | 时间与天气 | 天色、云、雨与远处灯光变化 | V2 |
| 抽屉、信封 | 留言与私信联系 | 拉开抽屉、展开信纸、填写并寄出 | V3 |
| 小黑猫 | 彩蛋 | 多次点击后伸懒腰，弹出隐藏对话 | V4 |
| 其他小物件 | 装饰、可选线索 | 按后续需要扩展 | V5 可选 |

书架映射文章集合，不为每篇文章制作独立模型。发布内容继续使用现有后台。

| 版本 | 用户能获得什么 | 版本完成后能否停止后续开发 |

| V1：可使用的书房博客 | 屋内 3D 首页、主要内容入口、完整阅读与降级能力 | 可以，已是完整博客 |
| V2：随时间天气变化的书房 | 实时环境、灯光、环境设置 | 可以，已有完整氛围系统 |

| V4：藏着秘密的书房 | 小猫动作、隐藏手记与可配置彩蛋 | 可以，完整探索版 |

各阶段按功能依赖推进，完成前一版本的必要验收后继续。资产、接口和设备验证属于开发任务，不以“默认已经具备”跳过；缺口落实到具体任务，不通过删掉必要反馈或验收来标记完成。素材采购和第三方服务开通按实际需要处理，与开发排期分开。

推荐按 V1 → V2 → V3 → V4 实施。若联系能力优先级更高，V2 与 V3 可交换；二者均只依赖 V1。

## 5. V1：可使用的书房博客

### 用户体验

打开网站直接进入书房，可拖动视角、小范围转头，点击书架、日记本、照片和电脑访问对应内容。使用固定的黄昏光照，窗外为静态景色。

该版本不等待真实天气、留言系统或小猫彩蛋完成即可上线。信封与小猫可先不出现，或仅作为无交互装饰。

### 开发任务

- [ ] V1-01：核实文章、时间线、项目、关于页、国际化与 SEO 的现有实现，明确复用边界。
- [ ] V1-02：确定屋内构图、风格、可见入口及桌面/手机镜头方案；完成沉浸首页与现有站点页头、页脚、顶部留白的布局隔离。
- [ ] V1-03：制作房间、家具、材质、固定光照，交付可编辑资产与授权记录。
- [ ] V1-04：接入 3D 场景，完成有限角度观察、点击检测与预设镜头过渡。
- [ ] V1-05：接入四个主要物件，完成列表、详情跳转及返回原视角，统一 URL、浏览器历史与内容状态。
- [ ] V1-06：实现低调导航、简洁模式、加载封面、加载重试与静态降级。
- [ ] V1-07：补齐触屏、键盘、焦点管理及减少动态效果支持。
- [ ] V1-08：保留有效内容 URL、语言路径、元信息与现有搜索收录能力。
- [ ] V1-09：完成代表性设备测试、资源优化、上线开关及回退验证。
- [ ] V1-10：实现至少一项窗帘或植物基础微动及桌面端轻微视差，并完成动态效果关闭和低性能降级；另一项可后续增强。
- [ ] V1-11：完成书架与日记本的连续运镜、物件展开、HTML 内容接管，以及可中断返回和声音同步。
- [ ] V1-12：筛选 threejsassets 免费候选与程序化资产，完成近景试装、可编辑结构检查和授权台账，再决定付费采购范围。

V1 的执行顺序：先完成 V1-01/02/12 的接口、构图和资产小样检查，再并行完善场景与内容，随后接入运镜、微动和适配，最后统一验收发布。任务编号用于追踪范围，不表示必须按编号串行施工；以上检查属于阶段内工作，不交付一个缺少正常阅读功能的半成品。

### 交互细节

- 常态不显示浮动文字，靠近时允许轻微材质或姿态反馈。
- 点击物件后及时反馈，再执行短过渡，不让访客怀疑是否点中。
- 手机直接点击进入；无需依赖悬停或双击发现主要功能。
- 内容面板打开后暂停房间点击，关闭后恢复原视角和焦点。
- 正文使用 HTML，不将长文章写进 3D 纹理。
- 从外部链接进入文章时直接阅读，不强迫先经过房间。

#### 内容与路由边界

- V1 日记本复用现有公开时间线，展示列表与单条内容的阅读视图，不新增私密日记、日记权限或完整富文本日记 CMS。当前时间线数据未必提供独立详情 URL，需检查字段；不承诺凭空获得文章式日记详情页。
- 内容页保留现有 canonical URL。房间内分类面板等临时状态可使用经校验的查询参数或浏览器历史状态，V1-05 固定一套映射表并验收，避免每个物件自行维护路由逻辑。
- 从房间进入正文时保存镜头、物件状态、列表滚动位置；返回时在同一浏览会话内尽量恢复。直接访问或刷新正文不依赖该状态，无记录时返回默认房间视角。
- 浏览器返回与关闭按钮走同一状态转换：先关闭当前内容层，再回到房间；不重复写入历史，不盲目调用 history.back 导致直接访问的用户离开本站。
- 语言切换通过稳定内容 ID 找到对应路由；缺少译文按现有规则回退或给出空态。数据刷新、空列表和链接失效不得重置摄像机或阻塞返回。

#### 输入与可访问性

- 区分点按和拖动：按下到抬起的移动距离超过阈值后仅转动视角，不触发物件点击；处理 pointer cancel、多指中断和指针离开画布，结束后清除拖动状态。
- 只在房间观察区接管拖动；阅读面板保持正常滚动、文字选择及浏览器缩放，不全局禁止触摸手势。
- 房间物件与 HTML 导航连接同一内容动作；键盘焦点可见不受“隐藏提示”约束。弹窗有可访问名称、合理的焦点约束与 Esc 关闭，背景内容不继续接受输入，关闭后恢复触发位置。
- 3D 尚未就绪时，服务端 HTML 导航直接可用；首次成功显示场景后再切换视觉层，模型失败不得留下遮住导航的透明画布或永久加载层。

### 视差与“微呼吸感”

即使访客不操作，房间也有极轻微的环境变化，让空间保持生命感。家具、墙壁、书本等固定物体保持稳定，避免整个房间像漂浮模型一样上下移动。

| 元素 | V1 基础表现 | V2 环境联动 |
| --- | --- | --- |
| 窗帘 | 下摆缓慢、轻微起伏，窗帘顶部固定 | 按天气预设调整幅度；关窗时仍保持克制 |
| 植物 | 少量叶片轻摆，各植物节奏错开 | 随环境预设小幅调整，不强行与现实风速一一对应 |
| 台灯光晕 | 开灯时有几乎不可察觉的柔和变化 | 与灯光开关、昼夜状态协调 |
| 镜头视差 | 指针移动时出现有限的微小观察偏移 | 保持同一套控制规则 |

实现规则：

- 静止时的生命感来自环境微动；视差由指针移动产生，不通过持续自动摇晃镜头制造。
- 使用单一 3D 摄像机的小幅位置偏移配合受限朝向补偿产生远近视差，不把家具当作独立图片层任意平移；仅旋转摄像机属于微转头，不称作深度视差。位置幅度在模型尺度固定后调参，并检查近处家具与窗口边界；与拖动观察共享控制，避免叠加失控。
- 初始调参范围：镜头偏转控制在约 0.3–0.6 度以内，环境微动周期约 6–12 秒，光晕变化约 1%–2%；均为可调整起点，不是必须达到的视觉强度。
- 台灯变化优先作用于灯罩发光材质或局部光晕，不持续重算动态阴影，不做明显明暗闪烁。效果若让人联想到接触不良，则取消该变化。
- 各元素使用不同周期和相位，避免同步摆动。微动不暗示可点击，交互反馈另外处理。
- 指针微视差仅在桌面空闲观察时启用；拖动、镜头过渡、物件动画或内容展开时暂停，恢复时平滑衔接。
- 手机保留少量环境微动，默认关闭指针视差，不启用陀螺仪控制。
- 开启系统“减少动态效果”或站内关闭选项后，停止循环微动与微视差，并降低交互过渡动画。
- 页面隐藏时停止动画；低性能模式逐步关闭光晕变化、叶片和窗帘微动，静态降级版不运行这些效果。
- V1 仅做简单程序化形变，不引入实时布料物理；V2 仅增加天气参数联动。完整布料模拟属于后续独立评估项。

基础微动纳入 V1，天气联动纳入 V2。V1 至少完成窗帘或植物的一项环境微动和桌面轻微视差；正常设备体现效果，低性能和减少动态效果模式允许关闭。两类微动均按简单形变设计；若现有植物网格不适合，采用可控的程序化叶片或窗帘实现。更多微动和精细光晕可在后续独立版本增强，不阻塞完整基础版本交付。

### “多米诺骨牌”式连续运镜

点击区域后，让镜头、物件和内容按顺序自然带动，形成一次连续动作，而非镜头停止后再突然弹窗。将其作为 V1 的书架和日记本基础交互，其他物件可复用同一套转场调度。

| 入口 | 镜头动作 | 物件动作 | 内容接管 |
| --- | --- | --- | --- |
| 书架 | 向书架平移并轻微侧转，保持目标区域清晰 | 镜头接近终点时，书架侧面的标签托板像抽屉一样滑出 | HTML 文章分类标签与托板位置衔接，随后展开列表；点文章进入正文 |
| 日记本 | 镜头下压、前推，平滑转为俯看书页 | 镜头接近时日记本自动翻开，书页逐渐占据主要视野 | 书页与 HTML 阅读容器对齐并交叉淡化，最终进入全屏日常阅读视图 |

日记本初始姿态采用合拢或半开状态，为翻开动作预留空间。最终阅读由 HTML 承担，支持选择文字、滚动、分享和键盘操作，不依赖放大 3D 纹理呈现正文。书架标签包含键盘可操作的真实链接；视觉托板只是承载界面的一部分。

#### 转场时序与实现

1. 点击后立即反馈并预取目标内容，保存原镜头位置、朝向及观察状态。
2. 暂停微视差、拖动观察与其他区域命中，启动镜头过渡。
3. 在转场进度约 60%–75% 时启动托板滑出或翻页，使动作适度重叠。
4. 接近最终构图时接入 HTML 内容，完成焦点移交，开放阅读和列表操作。
5. 关闭时先收回内容与物件，再平滑返回原观察位置；减少动态效果模式使用短淡化或直接切换。

建议书架完整转场约 0.8–1.2 秒，日记本约 1.0–1.5 秒，作为调参起点。动画使用共享时间轴与明确的完成事件协调，不用多个独立延时拼接，内容请求也不与动画结束时间强绑定。

- 摄像机位置可采用插值，旋转采用四元数球面插值；使用随时间推进的缓动曲线，避免逐帧固定比例 Lerp 导致设备间速度不同或永远无法精确结束。
- 镜头前推为日记本主要放大手段，必要时小幅调整视场角；固定终点并检查近裁剪面、桌面和书页穿模。
- 镜头路径预先检查障碍物，必要时使用中间点，避免直接直线穿过椅背、台灯或书架。
- HTML 接管后优先降低背景渲染开销，避免全屏阅读时仍运行完整场景。

#### 中断、声音与异常

- 转场期间重复点击不启动第二条动画；始终保留关闭/返回能力，返回时取消当前时间轴并从当前位置平滑恢复，不瞬移。
- 内容未就绪时提供可取消的加载界面，失败时显示重试与返回，不能让访客被锁在放大的空白书页中。
- 翻书声在书页动作开始时触发，抽屉声在托板移动时触发。音频资源按需预载，不以音频加载作为转场完成条件。
- 声音只在访客已开启声音后播放，遵循全局静音；浏览器阻止播放、音频失败或返回中断时，视觉流程仍正常完成，并停止对应音效。
- V1 即提供声音开关，默认关闭，用于翻页等交互音效；V2 在同一设置上扩展雨声等环境音，不重复建立音频系统。
- 手机使用单独校准的路径与终点，横竖屏切换时保持阅读可用；减少动态效果模式跳过长运镜和翻页动画。

该方案取代书架和日记本原有的简单靠近动画，不作为额外叠加动画。V1 交付预设路径、简单书本开合与 HTML 接管；复杂逐页翻书、真实纸张形变和任意视点自动避障不在首期范围。参考代码只是实现依据，不能代替实际集成与验收。

## 6. V2：随时间天气变化的书房

### 用户体验

房间默认呈现博主配置城市的当地时间与天气；访客也可手动切换晴朗午后、黄昏、雨夜。台灯可操作，声音由访客主动开启。

### 开发任务

- [ ] V2-01：配置城市、时区与天气供应商，确认配额、费用和服务可用性。
- [ ] V2-02：实现清晨、白天、黄昏、夜晚四种状态及平滑过渡。
- [ ] V2-03：实现晴、阴、雨三种天气表现，控制移动端粒子数量。
- [ ] V2-04：增加服务端天气代理与缓存，密钥只保留在服务端。
- [ ] V2-05：实现台灯自动状态与手动覆盖规则。
- [ ] V2-06：提供实时/手动预设、静音及环境设置的本地保存。
- [ ] V2-07：实现接口失败、数据过期、离线与低性能回退。
- [ ] V2-08：完成灯光、音频授权及性能回归验证。
- [ ] V2-09：将窗帘、植物微动与天气预设联动，保持手动环境选择、减少动态效果和性能降级规则优先。

### 状态规则

- 默认跟随配置城市，明确标注所用城市；不请求访客定位。
- 建议约 30 分钟刷新天气；以供应商限制与最终缓存策略为准。
- 手动预设不被天气刷新覆盖，选择“跟随实时”后恢复自动。
- 台灯手动操作后保持当前访问会话内的选择，自动切换不得立即反转。
- 使用最近有效天气；超过约定有效期后使用默认场景，并标明非实时。
- 声音默认关闭；只有用户主动开启后播放。

### 环境状态与服务边界

- 自动模式按城市时区计算昼夜；天气只控制云量、降水与光照修正，不能用“晴天”覆盖夜晚变成白昼。手动预设明确同时覆盖时间和天气；台灯手动选择只覆盖灯的状态。
- 设置优先级：静态/低性能模式与减少动态效果限制表现开销，其次应用手动环境预设，再应用自动时间和天气。画面降低效果不篡改所显示的天气数据。
- V1 的阅读深浅主题与 V2 房间昼夜分开管理；进入夜晚不改变读者已经选择的阅读主题。
- 雨夹雪、大雪、雾等首期不支持状态映射到已有阴/雨表现，天气文字仍保留真实含义；不会以缺少雪景为由阻塞自动模式。
- 天气采用站点级服务端缓存、请求合并、超时与有限重试，不为每位访客分别调用供应商。建议新鲜期 30 分钟、最近数据最多保留 2 小时用于展示，最终参数按供应商与实际调用预算在 V2-01 固定；超期使用非实时预设，保留更新时间。
- 首期用四段预设时段，不按经纬度计算实际日出日落；时段边界在 V2-02 固定为配置。页面回到前台重新对时，不一次性追赶后台漏掉的动画。
- 保存声音偏好不等于浏览器已允许播放；新文档需用户手势解锁音频，失败时显示静音状态，不影响场景使用。

### 交付与验收

- [ ] 时间与天气可独立模拟测试，跨时区和跨日正确。
- [ ] 接口异常不会阻塞首页，也不影响内容访问。
- [ ] 手动预设、台灯、静音与刷新行为符合规则。
- [ ] 雨景在目标手机上达到性能底线，否则自动降低效果。
- [ ] 不包含雪景、精确太阳轨迹或复杂玻璃水滴模拟。

### 写入、展示与运营边界

- 公开写入不要求访客登录；管理操作复用现有后台认证和角色权限。公开读取仅返回审核通过的展示字段，服务端不先查询整条私信再交由前端隐藏。

- 后台“回复处理记录”仅记录已处理或已通过外部联系方式回复，不包含站内往来会话或邮件发送系统。博主在 V3 上线前约定检查后台的频率，站点不承诺回复时限。

## 8. V4：藏着秘密的书房

### 用户体验

书柜下的小黑猫平时睡觉或探头。第一次点击睁眼，第二次甩尾，短时间内第三次点击后伸懒腰、走出来，弹出一句对话，邀请访客听一个小秘密。

### 开发任务

- [ ] V4-01：先以简化几何角色验证位置和互动，再落实正式低多边形骨骼 GLB 与睡觉、观察、甩尾、伸懒腰、短距离移动动作，记录授权与资产规格。
- [ ] V4-02：实现状态机、点击计数、触发时间窗、冷却及动作互斥。
- [ ] V4-03：制作可关闭的对话框及彩蛋内容展示页。
- [ ] V4-04：增加后台彩蛋配置，支持台词、目标内容、启停及排序。
- [ ] V4-05：制作并核实 3–5 条本站冷知识和一篇隐藏手记。
- [ ] V4-06：实现本地发现记录、内容去重与失效链接回退。
- [ ] V4-07：增加移动端命中区域、降低动画偏好适配与资源按需加载。
- [ ] V4-08：接入 AnimationMixer、动作过渡及资源释放，完成遮挡、移动路径、暂停恢复与加载失败验证。

### 小黑猫的正式技术方案

采用“低多边形 3D 小猫 + 骨骼动画 + 行为状态机”，使用独立 GLB 资产。角色位于书柜底部，融入房间透视、灯光和家具遮挡；身体使用黑灰层次与可辨认的眼睛，避免在暗处完全丢失轮廓。不采用二维贴图作为正式角色，不做毛发模拟或通用物理系统。

| 层次 | 技术和职责 |
| --- | --- |
| 模型 | 带骨骼与蒙皮的低多边形 GLB，统一尺度、朝向、地面高度与材质风格 |
| 动作 | Three.js AnimationMixer 播放动作片段，动作间短交叉淡化；一次性动作完成后按事件切换 |
| 行为 | 状态机管理点击、时间窗、动作完成、冷却、对话与返回休息 |
| 点击 | 独立命中区域跟随角色位置和姿态状态，检查家具遮挡与触屏可点性 |
| 内容 | React/HTML 对话框展示邀请，点击后打开后台维护的冷知识或隐藏手记 |
| 生命周期 | 角色按需加载，页面后台或阅读内容时暂停更新；释放时停止动作并清理独占资源，共享资源由缓存管理 |

#### 动作与状态

```text
睡觉 / 偶尔探头（轻微呼吸）
    → 第一次点击：睁眼、抬头观察
    → 第二次点击：耳朵转动、甩尾
    → 第三次点击：伸懒腰、走出来
    → 动作完成：出现可关闭的邀请对话
    → 点击继续：冷知识或隐藏手记
    → 关闭 / 冷却：返回休息
```

点击时间窗从第一次有效点击开始。抬头、甩尾等短反馈期间允许累计后续有效点按，但不重新启动当前动作；按状态依次完成后进入伸懒腰，避免快速连点被无反馈吞掉。伸懒腰、走出和对话期间不再累计点击。超时且尚未达到阈值时平滑回到休息并清零；动作顺序与计数不使用不同的独立定时器竞态实现。

短距离移动采用预设路径，统一由角色根节点负责位移，动作片段采用原地行走或去除重复根位移，避免骨骼和场景节点双重移动。路径需检查书柜、椅脚和地面，不引入自由寻路。

阅读或后台暂停不丢失对话与发现记录；恢复时避免累计过大的时间步长导致跳帧。减少动态效果模式关闭循环呼吸、压缩动作过渡，保留点击反馈及彩蛋内容。角色加载失败不影响博客和已上线功能，可允许重试或隐藏该入口。

小猫逻辑服从全局内容状态：书架、日记或信纸打开时禁止小猫触发新对话；离开场景时停止待触发回调。8 秒点击时间窗在页面隐藏或其他内容接管时清零，不恢复过期计数。其他时间按同一活动时钟推进，避免暂停后突然连播动作。

#### 资产落实与分工

- 助手负责简化程序角色原型、正式资产接入、状态机、命中检测、动作调度、DOM 对话及性能处理。
- 自然的猫体造型、蒙皮与伸懒腰动作优先寻找有明确授权的现成资产；没有合适来源时，由助手尝试程序建模、骨骼与动作制作，用户评审视觉效果。是否采购额外素材由实际质量缺口决定，不预设必须外包。
- 选型时逐项检查是否确实包含所需动作、骨骼兼容性、循环和一次性动作、材质表现、动画位移及许可；仅有猫模型不算资源齐备。
- 程序化椭球身体、耳朵与尾巴可验证体验，但动作会偏卡通，属于阶段内原型。若最终改为程序角色，须重新确认视觉目标并仍完成全套可用反馈，不将占位角色直接标记为正式骨骼版交付。
- V4 先落实正式资产路线，再完成模型、动作与集成。模型缺动作、动作不兼容、蒙皮不自然均作为本阶段待解决任务，不假定下载一个 GLB 就完成；效果未达标前不开放半成品彩蛋。

### 触发规则

- 初始方案为 8 秒内点击 3 次，原型测试后可调整。
- 短反馈期间可累计点击，但完整彩蛋每轮只触发一次；伸懒腰、走出和对话期间锁定再次触发，不叠加对话框。
- 对话只邀请继续探索，不自动跳转。
- 首次和后续对话可不同，发现记录无需登录。
- 彩蛋不承载必须完成的正常功能，不影响文章、日常和联系入口。
- 隐藏手记是未主动展示的公开内容，不是私密内容；不能把敏感信息仅靠隐藏链接保护。彩蛋只提供预定义内容或经过校验的链接，不接受后台注入任意脚本。
- 本地发现记录失败或被清除时允许重新发现，不阻塞彩蛋。屏幕阅读器与键盘用户有等价可操作入口，探索方式不依赖精细鼠标命中。

### 交付与验收

- [ ] 触发、关闭、重复访问与冷却行为稳定。
- [ ] 快速连点、慢速点按、超时清零与后台恢复均符合规则，反馈不被反复重启动作打断。
- [ ] 彩蛋内容可后台维护，不必重新导出房间模型。
- [ ] 目标关闭或失效后有可用回退，不出现死链。

### 现有基础

已检查前端依赖为 Next.js 16.1.3、React 19.2.3；已有文章、专栏、时间线、项目、关于等路由。项目说明记录了 NestJS API 与独立后台。具体接口、权限和数据字段须在 V1 核实，不能仅按项目说明假定全部可复用。

本次复审还核对了当前 `src/app/[locale]/layout.tsx`：传统 Header、Footer 与主区 `pt-20` 由语言布局统一渲染。V1 必须拆分页面壳，将全屏房间与普通阅读页布局分开，同时保留语言、主题和服务端元信息。优先用嵌套路由布局/路由分组保持原 URL，不通过挂载后再隐藏页头制造首屏跳动。现有语言标识为 `zh`、`en`；时间线已具备公开列表与图片展示，但不能据此假定有日记详情和私密权限。

### 推荐实现

| 模块 | 建议 |
| --- | --- |
| 渲染 | Three.js + React Three Fiber，锁定兼容版本 |
| 模型 | 程序资产代码或有权交付的建模源文件，以及运行时 GLB；纹理压缩与静态光照烘焙 |
| 场景加载 | 独立客户端模块，按需加载，避免拖累文章页 |
| 阅读 | HTML 内容面板与现有独立路由 |
| 动画 | 镜头、物件、小猫分别管理，由统一场景状态协调 |
| 天气 | 服务端代理、缓存与状态归一化 |
| 留言 | 现有后端新增独立模块、后台与权限 |
| 配置 | 物件到内容路由映射、城市、环境预设、彩蛋配置 |
| 分发 | 静态资源版本化，使用现有对象存储/CDN能力 |

关键场景状态包括：资源加载、自由观察、镜头过渡、物件动画、内容展开、错误回退。状态之间明确互斥，防止重复点击导致镜头和面板失控。

互斥主要约束观察、转场和内容接管的输入所有权；环境微动可在允许的场景状态中继续运行，小猫使用受全局状态约束的子状态机，不让所有无关动画排成全局串行队列。

### 资源与异步生命周期

- 房间内保持单一 Canvas、更新循环与摄像机写入源；切到普通正文页时允许卸载，镜头恢复信息独立于 WebGL 实例保存，不以全站持续占用 GPU 换取返回体验。
- 请求、模型加载和动画使用当前操作标识。关闭或切换目标后，迟到的响应不能重新弹出旧内容；可取消的任务取消，不能取消的加载结果按缓存/释放策略处理。
- 独占的几何、材质、纹理、音频、事件监听和观察器统一清理；共享资源按所有权保留，防止一个面板关闭就 dispose 仍在使用的材质。初始化与销毁需可重复执行，开发期重复挂载和上下文恢复不重复注册帧循环、监听或音频上下文。
- 字体、封面、模型及 Draco/KTX2 解码器按部署版本管理，检查 CDN 跨域、MIME、缓存和失败路径；内容页不得被房间依赖或资产预载拖慢。
- 本地存储读写加失败回退，拒绝存储或损坏记录不得使场景无法启动。所有服务端凭证保持在服务端，构建产物和浏览器不包含管理令牌。

日常运营应通过后台完成：发布内容、审核留言、维护彩蛋。涉及家具布局、角色动作和视觉材质的修改才需要调整资产与前端。

## 11. 通用验收、性能与发布

### 体验验收

- 每个版本均完成文章、日常、关于、项目及当前已上线功能的回归。
- 验证直接访问、刷新、分享、浏览器前进后退、多语言切换。
- 验证重复点击、快速返回、窗口缩放、手机横竖屏和后台恢复。
- 键盘焦点可见，关闭内容后焦点恢复；减少动态效果设置生效。
- 连续往返房间与正文至少 10 次，检查帧循环、事件监听、音频与渲染资源不持续累积；静态降级模式释放已无用途的 GPU 资源。

### 性能目标

以下为目标而非现有实测承诺。V1 早期固定测试机型、浏览器版本、网络速率、缓存状态和测试步骤，后续沿用。

硬性上线底线是：主要功能可达、输入与返回正常、失败可恢复或降级、无阻塞性崩溃。下表的加载时间、帧率与资源体积是优化目标；未达到时先调低效果或启用静态模式，记录实际结果，不能写成目标已达成，也不能为了房间效果牺牲正文可用性。

| 指标 | 目标与处理 |
| --- | --- |
| 加载 | 约定网络下 2.5 秒内出现可用封面和导航，争取 5 秒内可交互 |
| 帧率 | 代表性桌面争取 60 FPS，中端手机稳定 30 FPS |
| 资源 | 房间模型与纹理首轮传输预算争取 3–5 MB，不含延后加载内容 |
| 稳定性 | 模型失败、图形上下文丢失、天气超时均可恢复或降级 |
| 降级 | 轻量 3D → 静态房间与内容导航；用户可主动选择简洁模式 |

#### 可复现的测试记录

- V1-09 产出设备与网络基线表：设备型号、系统/浏览器版本、分辨率与像素比、网络速率/延迟、资源版本。至少覆盖普通笔记本、中端 Android 和一台 iPhone；实际没有的设备标记未测，不用浏览器模拟器冒充真机结果。
- 冷启动清空应用资源缓存，至少运行 3 次，记录范围与中位数；分别计量可用 HTML 导航出现时间、3D 首次可点击时间。3D 就绪包含下载、解码、GPU 上传与首帧准备，不以进度条到 100% 代替。
- 在基础设备档位与默认效果下，记录静止观察、拖动、书架转场、日记阅读四种状态的表现；连续运行 10 分钟后复测，观察卡顿、降频及上下文丢失。
- 自动降级的触发阈值、采样区间与恢复规则在基线验证后写入配置；避免一次卡顿就切档或持续来回切档。静态模式必须可手动选择，不能依赖性能检测成功才可进入。
- 记录失败注入：模型/解码器加载失败、内容请求超时、WebGL 上下文丢失；V2 起补天气失败，V3 起补留言响应丢失。检查恢复后输入、内容和资源生命周期。

通过减少动态阴影、限制像素比、复用材质、控制粒子、暂停不可见场景等方式优化。压缩体积不能代替显存和真实设备验证。

循环微动开启时需要持续更新画面，不能同时假定场景始终按需静止渲染。仅对当前可见且启用的动画更新，关闭微动后恢复按需渲染；在固定测试设备上比较开关前后的帧率与持续运行表现。若基础性能目标无法满足，优先减少环境微动，不牺牲输入响应和内容使用体验。

### 发布与回退

- 每阶段先发布可评审环境，验收后上线。
- 使用配置开关保留原首页或简洁首页作为回退入口。
- 资源文件带版本，确保前端与模型同步。
- 数据库变更尽量向后兼容；回退前端不得删除已收到的留言。
- 检查加载失败、天气异常、留言提交失败等必要日志，避免记录私信正文和联系方式。

## 12. 风险与评估决策

### 四类工程难点与选型约束

#### 视觉资产与性能

- 模型采用 GLB，比较 Draco 或 Meshopt 的体积、解码耗时与设备表现后选择；压缩不能代替减面、材质合并和减少绘制调用，也不要求同一几何重复使用两套压缩。
- WebP 可降低传输体积，但不能据此推断运行显存下降。纹理优先评估 KTX2/Basis GPU 压缩，结合尺寸、mipmap、材质数量验证实际内存；解码/转码资源需随项目可靠部署。
- 纹理图集、模型 LOD 与按需加载分别解决不同问题。书架、桌面近景优先细节，窗外小镇优先远景卡片或简化几何；仅在实际有收益时增加多级资源。
- 固定环境光遮蔽与间接光适合烘焙；不能把所有黄昏直射光和台灯效果永久烤进底色，否则 V2 夜晚或关灯时仍残留亮斑与阴影。
- V1 资产需为 V2 保留中性底色、可调灯光与独立发光区域。V2 对比少量预设光照贴图混合和轻量实时灯光，依据效果、纹理预算及手机表现选型；不默认同时加载多套高分辨率光照贴图。

#### 摄像机与空间状态

- GSAP 可作为统一时间轴候选，不强制引入；仅在现有动画方案无法清晰协调镜头、物件、音效时采用，避免多个库同时写摄像机参数。
- 曲线路径与缓动解决轨迹和速度感，不自动解决碰撞。首期使用经检查的有限路径与中间点，无需引入通用碰撞引擎。
- 屋内观察采用固定观察点的 yaw/pitch 限制；OrbitControls 默认围绕目标旋转，不能直接视为“转头”。若采用该控制器，需专门验证目标点、位置变化与空间边界。
- 状态至少覆盖观察、书架转场、书架内容、日记转场、日记阅读、返回和错误恢复，任意时刻只有一个控制源写入摄像机。

#### DOM 与 3D 融合

- 默认采用 3D 触发、短暂空间对齐、屏幕 HTML 接管，不将完整文章长期绑在透视变换的物体表面。
- CSS2D 适合位置锚定标签，不提供与物体表面一致的透视缩放；CSS3D 可提供空间变换，但仍需处理遮挡、事件、焦点与可读性，不默认引入第二套渲染器。
- 书架托板等局部内容可投影到屏幕定位，镜头稳定后再开放操作；发生遮挡或布局不足时切换正常内容面板。
- 内容样式保持书房的纸张与暖色视觉，玻璃拟态并非必要技术条件。

#### 跨端与持续性能

- 手机不是自动放弃 3D 的判据。以能力检查、运行表现和用户选择确定档位；默认限制像素比、关闭重后期处理，再按表现降级。
- 首期手机采用单指观察、点击进入、明确返回；不默认加入双指场景缩放，以免与有限观察范围、穿模和网页手势冲突。文章区域保留正常滚动与浏览器缩放能力。
- WebGL 上下文丢失时暂停更新、展示恢复反馈，尝试恢复后重建必要资源；重复失败进入静态模式，已填写留言不得因此丢失。
- 测试覆盖持续运行与发热后的降频表现，不能仅用打开后几秒的帧率验收。

### 实施顺序补充

V1 内先用简化几何验证屋内构图、镜头和设备表现，同时接入真实内容接口完成一条阅读闭环，再替换正式资产。不能到美术与运镜全部完成后才验证业务数据。阶段内检查点无需单独上线，V1 最终仍按完整可用博客验收。

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 美术风格反复 | 建模、材质和光照返工 | V1 内先确认构图和小样，再完成资产 |
| 手机性能不足 | 发热、掉帧、流失 | V1 早期真机验证，逐版本性能回归 |
| 提示过隐蔽 | 找不到文章 | 首次访客测试与常驻低调导航 |
| 屋内视角遮挡 | 入口不可见、点击困难 | 独立手机镜头、命中区域与遮挡测试 |
| 内容接口不匹配 | 列表、详情或语言映射无法直接复用 | V1 首项核实接口并落实适配任务 |
| 天气供应商不可用 | 氛围失真 | 缓存、过期标记和默认场景 |
| 留言垃圾内容 | 运营负担与信息泄露 | 审核、限流、公开私密隔离 |
| 彩蛋持续扩张 | 当前版本边界不清、难以验收 | V4 限定内容量，小游戏单独交付 |

付费模型、音效、天气服务与资源流量按实际需要记录；不加入人员报价。高精度美术、多房间、自由行走等扩展需先明确交付边界，再决定是否纳入后续版本。

## 13. 推荐决策

### 美术资源分工与能力边界

美术是本项目的核心投入。AI 效果图用于确认方向，不能直接视为带有完整几何、材质、骨骼和动画的 3D 房间。正式资产需在场景中验证近景质量、形变、灯光与性能。

| 资源或工作 | 助手可承担 | 用户需提供或决定 | 需特别验证的质量难点 |
| --- | --- | --- | --- |
| 风格与构图 | 制作概念效果图、配色、镜头方案、资产清单 | 确认喜欢的风格与房间细节 | 需要更强原创艺术表达时 |

| 灯光与环境 | 实现程序灯光、天空、雨景、光晕和环境参数 | 确认氛围、城市与时区 | 高质量多时段烘焙、复杂光照资产 |
| 图片与装饰 | 生成插画、装饰画、纸张图案及纹理候选，处理已有图片并接入 | 个人照片、真实手稿等可选内容；确认使用权限 | 要求无缝纹理、成套 PBR 材质与精确风格匹配时 |
| 内容界面 | 制作纸张式阅读界面、文章标签、信纸表单与响应式布局 | 提供或确认文案 | 非必要 |
| 简单物件动画 | 实现抽屉、信封、书本开合、镜头、程序化叶片与窗帘微动 | 确认节奏和效果 | 复杂纸张形变、真实布料模拟 |
| 小黑猫 | 简化几何角色、程序动作原型；接入兼容模型与已有动画 | 选择简化风格、授权素材或定制路线 | 自然的猫体造型、蒙皮与睡醒伸懒腰等高质量动作 |
| 模型优化 | 检查与调整尺寸、材质、命名、压缩、加载和运行表现；工具可用时执行批处理 | 提供源文件或授权资源 | 复杂重拓扑、UV 修复、手工减面和精细烘焙 |
| 声音 | 接入翻页、抽屉、雨声，调整音量和触发时机 | 提供录音或选择有授权的声音；付费采购由用户处理 | 定制拟音或原创配乐 |
| 素材授权 | 整理来源、授权条件、署名和资产清单，辅助筛选 | 付费、账号授权和最终采购选择 | 有法律疑问时另行确认 |

执行前需检查本机建模、压缩和音频工具。工具不可用时明确缺口，不承诺已经能够完成 Blender 源资产或高质量角色制作。程序几何可保存为可维护的代码资产，但不能据此声称已有人工精修的 Blender 源文件。

### 用户最小参与范围

1. 确认风格与质量目标：接受程序化风格化书房，还是投入授权模型/定制美术以贴近效果图。
2. 提供真实个人内容：关于我、联系方式、冷知识、隐藏手记；照片和手稿可选，可先用明确的装饰内容替代。
3. 决定素材预算，处理需要本人账号或付款的采购；不要求用户自己制作模型。
4. 在构图、正式视觉与上线验收节点做集中确认，避免逐个小物件反复确认。

### 推荐资产路线

- V1 先采用程序化风格化房间，必要时搭配少量有授权的近景材质或家具，确保交付真实可用版本。
- 基础材质、比例和灯光保持统一，不以堆砌高精度素材追求效果图。
- V2 复用资产，增加环境效果；V3 使用简单抽屉与信封动画；V4 根据小猫质量目标决定简化角色或专业资产。
- 若要求与概念图接近的木纹、织物、植物与角色表现，应在 V1 正式制作前单独落实美术来源和预算。
- 按用户与助手两人协作执行；助手负责程序制作、资源筛选、集成与验证，用户提供个人内容、做视觉评审并处理本人账号与采购。复杂造型、蒙皮、烘焙的质量不能仅靠代码承诺，应通过小样确认，不预设必须引入额外人员。

### 阶段启动前需落实的信息与资产

| 阶段 | 必须落实 | 不需要提前准备 |
| --- | --- | --- |

| V2 | 展示城市与时区、天气供应商和额度、环境声音来源 | 雪景、雨滴物理模拟 |
| V3 | 联系文案、隐私提示、后台接收与审核责任、表单规则 | 实时聊天、邮件自动回复 |
| V4 | 正式猫模型与动作、冷知识和隐藏手记、素材授权与预算 | 独立小游戏、账号收集系统 |

尚未确定供应商、素材或预算的条目保持待落实，不视为已购买、已获授权或已具备资产。用户不需要自行建模；助手能完成的程序和接入工作按上表执行，专业资产缺口另行落实。

概念图只作为构图和氛围参考，后续实现以本计划的屋内视角、性能与版本验收为准。正式可编辑资产按来源交付：程序代码、可转交的建模工程或允许修改的文件；不承诺转交未获授权的第三方源文件。

先立项 V1，并把构图、交互发现率、手机性能作为阶段内早期检查点。V1 的最终交付必须是可正常使用的完整博客，而不是只展示场景的演示。

上线 V1 后，可根据反馈决定继续环境系统或优先联系功能；V4 的小猫与彩蛋最后加入。任何后续阶段暂停，都不影响已经交付版本的正常使用。
