# V3 书房来信 · 验收与发布

本版交付免登录寄信、博主收件箱、经授权和审核的公开信件，以及完整画质下的一次性性能建议。访客在抽屉或导航打开「给我写信」，独立页为 `/zh/letters` 和 `/en/letters`。后台入口是「内容 → 书房来信」。

## 权限和数据流

- 昵称、正文、邮箱必填，手机号和主题可选。访客自行勾选公开授权，默认私密。联系方式为自填信息，可在管理员详情中查看。
- 私信直接进入收件箱；允许公开的信进入待审。管理员可公开或保留私密，已公开的信可撤回。公开接口只读取昵称、正文、发布时间与随机公开标识。撤回后的新请求立即生效；读者已经打开的旧页面无法远程抹除。
- 后台使用 JWT 和数据库中的当前管理员角色。用户管理的创建、代改和删除也校验角色，自助修改个人资料保留。公共写入按来源每十分钟三封、全站默认每十分钟 120 封。相同提交编号和内容复用原回执。请求结果未知时，信纸保留并提供「确认上次寄送」。
- 联系方式使用 AES-256-GCM，密文与信件编号绑定。索引使用另一个密钥做 HMAC。浏览器生成的认领凭条仅以摘要入库，未来账号系统需验证邮箱并逐封认领。当前版本没有访客登录和按邮箱公开查询功能。

## 发布配置与恢复

1. 在部署端密钥管理中生成独立的 32 字节随机值，十六进制编码，分别赋予 `LETTERS_INDEX_KEY` 和 `LETTERS_CONTACT_KEY_1`。设置 `LETTERS_KEY_VERSION=1`。同一集群共用密钥，单独备份。轮换联系方式密钥时增加下一版本并修改活动版本，旧密钥保留至旧密文及备份到期。查询密钥变更需要重建索引并处理幂等指纹。
2. 为 API 配置 `LETTERS_PRIVACY_JOURNAL`，指向数据库备份之外的持久文件。预建空文件，目录仅授予服务账号写入，独立备份；多实例共用可靠的追加日志。删除和撤回写入该记录并同步到磁盘。配置 Redis 及所有实例共用的 `LETTERS_QUOTA_NAMESPACE`。确认管理员收件账号、数据保留期限和备份可恢复。
3. 先备份 PostgreSQL。在候选环境应用追加式迁移 `20261108180000_study_letters`，运行 `prisma generate`、`prisma migrate deploy`。部署包含新模块的 API、后台和前台及 HTTPS 实际生效站点的来信限流规则。生产入口转发到 `/v1/public/letters`，后台沿用 `/api/admin/letters`。浏览器公开列表禁用缓存。包中同时携带 `scripts/replay-letter-privacy.cjs` 与 `scripts/prune-letter-tombstones.cjs`。
4. 确认写入、无权限拒绝、审核公开、撤回和删除。按日统计新信、成功重试、429 命中来源/全站规则、503 以及请求总量，仅保存计数。限制全站写入可调整 `LETTERS_GLOBAL_PER_10M`。上游代理须覆盖可信来源地址，API 仅向代理提供服务。
5. 回退应用时先停收件，切回上一个前台、后台和 API 版本，保留新表、密钥与独立日志。需要恢复数据库时先断开对外访问，恢复备份后在 API 目录运行 `node scripts/replay-letter-privacy.cjs --offline-restore`。使用完整的独立日志；任一行损坏或执行失败，先修复再开放。重复执行安全。
6. 已处理私信在后台满 90 天提醒复核。删除清空正文、联系方式、认领摘要。设置 `LETTERS_BACKUP_RETENTION_DAYS` 为覆盖所有可恢复备份的实际期限，运行 `node scripts/prune-letter-tombstones.cjs` 查看过期数量，加 `--apply` 清除。撤回和删除日志只在相应备份及重试窗口全部过期后按归档周期清理。

## 可重复验收

- 博客运行 `pnpm test`、书房 ESLint 与 `pnpm build`，后台运行 `pnpm exec tsc --noEmit --declaration false`、`pnpm build`，API 运行 Jest 与 `pnpm build`。
- 本地启动独立 API、PostgreSQL、Redis，配置 `NODE_ENV=study-preview`、专用密钥、以 `studyv3_` 开头的库名和以 `studyv3-` 开头的限流命名空间。在 API 目录运行 `node scripts/check-study-letters.cjs`。Windows 与 WSL Ubuntu 环境可附加 `--wsl-restore` 实际演练备份、恢复、二次重放。
- 实测覆盖并发同号写入、冲突、私信隔离、无权限拒绝、邮箱等值查询、限流边界、Redis 故障与恢复、公开分页、撤回和清除。另有前端响应丢失重试、凭条摘要和主动恢复画质的自动回归。
- 本地 Chrome 打开书房的 `?roomDiagnostics=1`，在同一视角分别运行完整效果与性能模式，查看采样时间、持续绘制帧数、长帧、像素比及资源计数。静态挂钟走秒单独计数。目标 PC 的两档实测记录见下文。

前台 123 项、服务端 453 项测试通过；服务端原有 6 项跳过。前台、后台和 API 构建通过，书房 ESLint、后台类型检查和 6 项发布辅助脚本测试通过。Redis 断开与恢复、并发投递、权限、限流、同时间分页、审核和清除另行在真实服务上验收。实际 PostgreSQL 备份恢复后连续重放两次，撤回与删除状态均正确。将上一个 V2 提交构建的 API 连到同一已迁移的隔离库，健康检查及文章返回 200，来信接口返回 404；切回 V3 后收件正常。
