# 搜索升级 V1：组合关键词与相关性

日期：2026-11-06。PR #9 已合并，与书房 V1 收尾一起上线。此版本为基础检索升级，不包含语义向量检索。

## 解决的问题

线上曾验证：`隐式动画与显式动画` 为 3 条，改成 `隐式动画 显式动画` 为 0；`Flutter 动画` 为 2 条、`动画 Flutter` 为 0；`Fluter` 为 0。两个入口搜索 `TickerProviderStateMixin` 分别为 8 条和 0 条。完整标题还会排在正文上一篇链接引用之后。

## 已实现

- 两个 API `/v1/public/search?q=…` 和 `/v1/public/articles?search=…` 复用同一查询，保留传统列表字段与书房字段。
- NFKC、英文大小写和空白归一化；中文采用运行环境 ICU 分词结合最长技术词典，保护隐式动画、显式动画及常用技术名称；并非完整中文 NLP 或意图理解。
- 多组关键词之间 AND 匹配，组内术语别名 OR 匹配；允许出现在不同字段、不同顺序，未偷偷丢掉未命中的关键词。
- 精确标题优先，标题短语其次；词项权重标题 100、标签 50、摘要 30、正文 5。日期和 ID 作为稳定的并列排序依据。
- 中英文别名维护在 `article-search.ts`，如依赖注入/dependency injection；英文纠错仅对长度至少四个字母的输入，在有限技术词表内做一次编辑修正。不会任意改写 API 标识符或全部英文单词。
- 排序在 PostgreSQL 中对全体匹配文章计算，返回已排序的 ID 后分页，仅 hydration 当前页详情，不先取第一页再在前端重排。查询继续限制已发布、语言、分类和标签。
- 所有输入参数化传递，并转义 LIKE 的 `%`/`_`；摘要仅输出转义文本与 mark 标记。前端以 React 文本节点展示，支持多个关键词/纠错后的高亮，不插入任意 HTML。
- 搜索请求最多 200 字符、16 个有效词项；书房代理保留 400 校验状态，前端提示缩短查询；接口/网络故障仍可重试。

## 工程边界

第一版复用现有数据库，无新增扩展、依赖或迁移。它仍使用按词项的包含判断，尚未引入倒排全文索引；因此长正文和更多文章会增加扫描开销。全局结果 ID 列表用于精确总数和统一分页，适用于当前约七百篇的规模；并非海量索引方案。上线前应对真实数据量测耗时，后续依据实测切换预分词全文索引，不把小样本测试当作生产性能承诺。

中文词典是可维护的有限覆盖。自由问句、同义表达、无共同字词的查询仍可能没有结果，不能把这一版称为已完成语义搜索。

## 验收

- 单元测试覆盖分词、术语保护、别名、拼写修正、查询长度、参数化与 HTML 安全摘要。
- 服务测试覆盖两个入口同样的排名、正文覆盖、分页总数、越界页和 hydration 顺序不影响结果。
- 独立 CI PostgreSQL 16 容器内创建事务临时表，执行真实 SQL，验证换序、目标标题排第一、正文/标签、语言/发布状态/分类/标签过滤及字面下划线。无生产数据库写入。
- 前端测试覆盖多词高亮、安全文本、旧响应兼容、400/503 区分、分页及语言映射。
- CI 同时执行后端生产构建与前端生产构建/standalone 冒烟。CI 链接与最终测试结果见 PR #9。
