日期：2026 年 11 月 5 日

状态：开发计划基线。用户已授权直接推进，独立工作区位于 D:/demo/black-cat-companion。公共行为、协议与模拟宿主已开始验证，正式视觉、资产、供应商和预算待用户集中确认。执行情况见 [独立工程进度](D:/demo/black-cat-companion/docs/progress.md)。

## 1 已确认的产品要求

| 编号 | 已确认要求 | 对实现和验收的约束 |
| --- | --- | --- |

| R04 | 使用正式猫模型、骨骼与动作 | 正式验收包含模型观感、绑定、动作过渡、接触点和资源开销 |
| R05 | 支持连续点击状态机 | 定义点击累计、反应升级、打断、冷却和恢复规则 |

## 2 最终体验与产品范围

### 2.1 用户体验流程

1. 用户打开独立演示，猫完成加载并自然进入待机；无需模型密钥即可开始互动。
2. 房间内存在明确的活动区域、休息点和靠近目标。猫低频移动、观察或休息，避免机械地等间隔重复同一动作。
3. 用户点击猫，立即获得轻微反馈；连续点击按规则升级反应，特殊条件可触发台词或动作彩蛋。
4. 用户进入模拟阅读页面，猫进入安静陪伴状态，避免挡住内容与控件。用户可收起、唤回或主动对话。
5. 用户主动聊天时，猫正常回应。结束对话后恢复与当前场景一致的日常行为，不强制用反问延长对话。
6. 用户请求帮助时，Agent 查询公开示例内容、展示来源，并通过允许的工具执行模拟页面操作。执行结果与实际界面状态一致。
7. 用户主动开启语音后才能使用麦克风。授权失败时仍可文字聊天；插话后声音和任务状态按既定规则处理。
8. 发现彩蛋后出现轻量反馈；重新打开应用时按所选存储模式恢复记录。
9. Agent、网络或资源出现故障时，界面明确显示可理解的状态，并保留能继续使用的功能。

### 2.2 首个完整独立版本

| 范围 | 完整版本应交付的内容 |
| --- | --- |
| 宠物表现 | 一套正式黑猫资产、动作与过渡、空间移动、点击互动、固定台词、阅读陪伴 |
| 趣味内容 | 一组经过编排的台词与动作彩蛋、发现反馈与记录；数量在内容表冻结时确定 |
| 管理能力 | 独立配置控制台与参考服务、配置校验、草稿预览与启用、发现记录查看与重置 |
| Agent | 文字聊天、公开内容查询、少量允许的操作、任务回执、取消、预算与错误处理 |
| 语音 | 可选开启、转写、发声状态、打断与文字降级；独立开关，不能成为宠物运行前提 |
| 可复用交付 | 包入口、类型、文档、示例、可分发资产方案、包外安装验证 |
| 独立演示 | 无 Agent 演示、Agent 调试页、完整演示、配置与记录控制台 |

操作系统原生桌宠、跨任意网站的浏览器控制、复杂成长经济、长篇剧情、任意第三方插件市场不属于当前完整版本。网站内的阅读陪伴属于本期范围；网页关闭后继续活动需要另立桌面应用计划。

### 2.3 表达与主动性

- 日常台词简短、自然，有猫的观察与反应；避免每句话固定加“喵”。
- 查询和解释时优先保证内容准确、结果清楚，人设不能遮掩错误或权限限制。
- 默认不主动采集麦克风，不因长时间无互动而持续追问。
- 主动靠近不必同时弹出文字；阅读时关闭主动搭话。
- 保留收起、静音、停止和关闭自主移动的入口，操作应能通过键盘完成。
- 人格细分、写实程度、名字和最终台词风格仍待视觉与内容评审确定。

## 3 独立工程与交付边界

### 3.1 工程归属

正式开发建议使用独立仓库与工作区。当前博客中的本计划仅用于保存需求和交接，不代表将宠物实现放入博客目录。仓库名称、npm scope、包名在启动阶段确定并检查可用性。

独立工程应能在新的目录安装、构建和启动。除显式启用真实 Agent 与语音的场景外，不需要博客服务、现有环境变量、私有资源域名或管理员账户。

### 3.2 建议的最小目录结构

下列名称为设计示意，正式命名在阶段 P0 确认。开始时保持一个宠物 npm 包和独立服务应用，只有依赖体积、团队协作或版本管理产生明确需求时才拆更多包。

```text
black-cat-companion/
  packages/
    pet/
      src/core/          行为调度、点击规则、彩蛋规则与状态
      src/contracts/     消息、动作、回执、适配器与配置类型
      src/web/           场景渲染、资源加载与浏览器生命周期
      src/react/         React 封装与上下文
      src/agent/         可选的浏览器 Agent 连接适配器
  apps/
    pet-lab/             独立房间与阅读演示、行为调试
    pet-console/         配置与发现记录控制台
    pet-service/         配置、记录和管理鉴权的参考服务
    agent-lab/           不依赖猫模型的 Agent 调试页
    agent-server/        模型、工具、会话与可选语音接入
    companion-demo/      两模块完成后进行独立集成验收
  examples/
    plain-web/           原生浏览器消费示例
    react/               React 消费示例
    nextjs/              SSR 宿主消费示例
  fixtures/              示例内容、场景、模拟工具与故障脚本
  asset-manifests/        模型、动作、贴图的版本与授权清单
  docs/                  产品、API、内容、测试与发布说明
```

上述应用是交付职责划分，不要求每项都维护一套独立部署与框架。实验室和控制台可以共用开发壳，服务可以共用基础设施；公共 npm 包始终不依赖这些应用。参考服务的框架与数据库在 P1 评估，避免为了演示引入整个博客后端。

### 3.3 两个业务模块

| 模块 | 负责 | 不应依赖 |
| --- | --- | --- |
| 宠物模块 | 猫的模型、渲染、动作、空间行为、点击互动、固定对话、彩蛋、配置与发现记录 | 模型供应商、博客路由、博客管理员凭据 |
| Agent 模块 | 理解用户、公开内容检索、工具编排、动态回复、会话、取消、预算和可选语音 | 正式猫模型、猫的骨骼结构、具体房间坐标 |
| 宿主适配层 | 提供场景、阅读状态、允许的导航与设置操作、内容源和存储实现 | 内部骨骼细节与模型推理细节 |

固定对话的数据与触发规则属于宠物；动态回答属于 Agent；对话界面只消费统一的消息与状态。后台与服务分别隶属于各自模块，不合并成一个高权限通用后台工具。

## 4 宠物表现与行为规则

### 4.1 正式模型与资产

先用代表动作链验证绑定、方向与接触点。建议先看待机、起步、行走、停下、坐下、恢复待机。样片通过后，资产负责人按 D02 清单执行 C07，制作或取得全套模型、骨骼、贴图和动画。交接时逐项核对可编辑源文件、运行资源、动作映射和对应的再分发许可，提交房间远景与阅读小尺寸的实际回放供用户审片。工程线同期使用占位猫验证行为。

| 资产项 | 交付与验收内容 |
| --- | --- |
| 模型 | 黑猫轮廓、面部可读性、体型比例、近远景尺寸、正侧背面效果 |
| 骨骼 | 身体、四肢、尾巴及表达需要的耳部或头部控制；命名与层级文档 |
| 贴图与材质 | 明暗背景均能辨识；毛发表现、透明与阴影策略符合性能预算 |
| 动画片段 | 稳定 ID、循环属性、时长、可打断位置、过渡要求和必要事件标记 |
| 移动 | 明确使用原地行走驱动位置，还是根运动；按选定方式统一速度与步幅 |
| 导出 | 比例、朝向、地面高度、包围盒、贴图路径和压缩加载方式一致 |
| 来源 | 原始文件、制作或采购来源、许可证、修改权与再分发权限 |

建议动作范围：待机观察、转向、行走、坐下、趴下、睡觉、醒来、伸懒腰、舔爪、伸爪互动，以及少量特殊反应。动作可由片段组合，不要求每个名称对应独立文件。说话优先通过眼神、头部、耳朵、尾巴与姿态表达；精细口型不是首版资产的默认前提。

### 4.2 行为调度

将身体动作、场景模式、对话状态和业务任务分别保存，避免合成一个庞大枚举。调度器依据这些状态决定可播放的动作与过渡。

| 状态维度 | 示例 |
| --- | --- |
| 场景模式 | 房间、阅读、收起、暂停 |
| 身体动作 | 待机、移动、坐卧、睡眠、互动、特殊动作 |
| 对话状态 | 空闲、倾听、等待、发声、错误 |
| 任务状态 | 待执行、执行中、成功、失败、结果未知、已取消 |

调度规则：

1. 关闭、卸载、资源错误和用户明确的停止控制优先处理。
2. 用户主动交互优先于普通自主行为；是否中断当前动画，依据该动作的中断标记处理。
3. D03 为房间靠近定义触发前提、观察时段、允许次数与最短间隔，至少选一条预期会靠近的固定种子轨迹。进入阅读即停止待播的自主台词与主动语音，限制自主移动和动作强度。用户主动互动后可获得回应，结束后恢复安静。具体节奏在 P3 试演后定稿并重跑同组用例。
4. 特殊动作可以短暂占用身体通道，但不能阻塞停止、收起等控制。
5. 同类重复动作合并；队列有长度和有效期上限，不能积压无限反应。
6. 视觉上的不耐烦反应不能自动取消正在执行的 Agent 任务。
7. 动作结束后按当前场景恢复，不能一律恢复到房间待机。

每个动作需列出允许的起始状态、退出状态、可打断规则和最大持续时间。行为时钟与随机数可注入，便于回放和测试。

### 4.3 连续点击

点击规则作为可校验配置保存。参数表至少包含累计窗口、阶段阈值、阶段动作、台词池、冷却时长、退出条件，以及触摸和键盘输入的等价行为。

| 情况 | 预期行为 |
| --- | --- |
| 首次点击 | 及时给轻反馈，不必等待双击判定结束 |
| 累计窗口内再次点击 | 升级反应或更新待执行反应，避免从头重播同一动画 |
| 高频点击 | 合并事件，限制播放和台词频率，不触发连续网络请求 |
| 冷却期间 | 采用轻反馈或合并处理，不能每次重触发彩蛋 |
| 用户开始聊天 | 点击升级与对话焦点按冻结规则协调，不抢占输入 |
| 切换阅读或收起 | 清理过期点击状态，记录规则明确 |
| 动画缺失 | 使用安全替代动作，点击状态仍能正常结束 |

具体次数和毫秒值由 P0 交互稿与 P3 实测共同确定。正式实现必须覆盖阈值前后、窗口边界、冷却边界和快速输入测试。

### 4.4 房间移动与阅读陪伴

独立实验室提供简化房间，包含可走区域、障碍、休息点和可被用户指向的目标。初版优先验证受限区域内的移动，不以完整室内导航系统为前提。

- 场景适配器提供坐标系、地面、活动边界与语义目标；核心逻辑不包含博客坐标。
- Agent 使用“窗边”等语义目标 ID，宿主将其解析为可达位置。
- 目标不可达、障碍更新或场景切换时，返回明确结果并安全停止。
- 阅读模式提供独立的陪伴位置与镜头规则；是否允许拖动在 P0 确定。
- 宿主可提供正文、按钮和输入框的避让区域；窗口变化后重新约束位置。
- 页面恢复时校正时间与状态，不能补播后台积压的整段动作。
- 同一正式模型是否同时适用于房间与阅读镜头，由 P1 视觉和性能实验决定。

### 4.5 固定对话与彩蛋

内容表至少包括 ID、版本、触发条件、前置条件、台词、动作、重复策略、冷却、发现记录规则和本地化字段。概率内容应支持固定随机种子复现。

每个彩蛋使用稳定的 `eggId` 标识内容。每次满足条件并获准触发时，生成新的 `occurrenceId`，将其写入发现事件，离线补传和失败重试沿用原值。按档案与 `eggId` 汇总次数，按档案与 `occurrenceId` 去重。持久化端在同一次原子更新中登记事件并更新计数。表现层按发生事件处理反馈，同一事件回放时保持提示次数。

纯浏览器包中的资源和规则可以被开发者检查，不能承诺严格保密。若某些触发条件需要服务端保管，使用独立规则接口并承担离线不可用的产品取舍。首版不设置反作弊要求，个人记录可由用户重置。

Agent 默认只获得已发现内容和允许公开的线索。未发现彩蛋的完整触发条件不自动进入对话上下文。

## 5 后台配置与发现记录

### 5.1 配置职责

独立控制台用于实际编辑和验收，不依赖博客管理系统。公共包消费经过校验的运行配置，管理身份、编辑权限和审计由参考服务或宿主负责。

| 配置类别 | 允许配置的内容 |
| --- | --- |
| 展示 | 模型与资源清单、尺寸、默认位置、主题、阅读表现 |
| 行为 | 动作映射、自主活动频率、活动范围、优先级内的有限参数 |
| 点击 | 阈值、窗口、冷却、反应映射 |
| 内容 | 固定台词、彩蛋触发项、重复策略与线索 |
| 能力 | 是否显示聊天、语音、发现记录入口及相应连接配置 |

配置不能包含任意可执行脚本、服务端密钥或提权规则。模型和资产地址设置来源约束。编辑、校验、预览、启用、恢复上一有效版本构成完整流程；运行中不兼容的资产变更应等待安全点或明确重载。

运行配置具有 `schemaVersion` 和 `configVersion`。应用内置安全默认值，加载失败或配置无效时保持上一有效版本。控制台明确展示草稿与当前启用版本，避免预览修改直接影响所有使用者。

### 5.2 存储模式

| 模式 | 用途 | 必须说明的限制 |
| --- | --- | --- |
| 内存 | 演示、测试、隐私模式 | 刷新后丢失 |
| 浏览器本地 | 独立离线宠物、匿名个人记录 | 清理站点数据后丢失；不自动跨设备 |
| 服务端适配器 | 已登录用户、需要跨设备记录的宿主 | 需要身份、授权、同步和删除机制 |

发现记录与 Agent 记忆分开。参考服务演示管理者查看、筛选和重置发现记录；若需要集中保存访客数据，应先确认数据范围、保留期与身份策略。

记录按档案保存彩蛋 ID、首次与最近发现时间、累计次数和内容版本。服务端从可信会话确定档案归属。本地与服务端适配器均保留用于重试去重的发生事件标识，覆盖约定的离线重传窗口。D04 明确多标签页、同步、重置、迁移和窗口过期后的处理规则。

## 6 Agent 开发范围

### 6.1 独立输入与知识

Agent 调试页先使用固定公开示例文章、站点说明和模拟页面状态。内容提供器接口支持搜索、按 ID 读取、来源地址与版本；后续博客只需实现相同接口。

知识、用户偏好和会话历史分别管理。回答以实际查询结果为依据，没有结果时明确表示未找到。内容修改、删除、下线后，缓存和未来检索索引要有失效机制；最终返回与导航前检查目标仍可公开访问。

先用真实问法测试关键词检索的效果，再决定是否引入全文或语义检索。不能通过扩大上下文，把全部文章和全部聊天历史长期塞入每轮请求。

### 6.2 工具能力

首批工具以以下能力为候选，最终名称和参数在 P0 契约阶段冻结：

| 工具职责 | 独立环境实现 | 博客接入后的实现 |
| --- | --- | --- |
| 搜索公开内容 | 查询 fixture 内容库 | 调用公开内容适配器 |
| 读取公开文章 | 按稳定 ID 获取示例正文 | 读取仍公开的文章 |
| 打开文章 | 打开模拟阅读页并回执 | 宿主导航并回执 |
| 跳转章节 | 模拟页面的稳定章节 ID | 宿主等待页面就绪后滚动 |
| 设置主题 | 设置明确目标主题 | 调用宿主主题接口 |
| 移动猫 | 请求走到已注册目标 | 同一宠物控制器执行 |

公开查询可以独立并行；导航与章节滚动等有依赖的动作顺序执行。设置型工具使用目标状态，例如设置深色主题，而不是“切换一次”。

不提供通用管理员工具、任意脚本、任意网络请求和数据库查询。未来新增留言、收藏等写操作时，另行定义权限、确认、去重和验收，不通过开放现有管理 MCP 获得能力。

### 6.3 执行可靠性

- 将工具允许列表与本轮用户授权分别校验。查询和总结默认只开放读取。服务端依据本轮用户的明确指令，或用户点击的具体操作按钮，向执行端授予指定动作和目标，并绑定轮次、页面版本、有效期与可执行次数。意图含糊时先展示候选动作供用户选择。正文、检索结果和模型生成的工具参数没有授予操作权限的能力。执行端还要检查身份、资源权限、完整参数和预算。
- 流式工具参数在完整接收并校验前不能执行。
- 操作使用稳定 ID；需持久化的 ID 在副作用发生前保存，重试不能生成新的业务身份。
- 工具契约声明回执保管方、保留期和能否查询历史结果。支持恢复的工具由执行端按 `commandId` 保存终态，同一会话重连后查询原记录。临时页面动作若遇到实例销毁、记录过期且缺少可信回执，以“结果未知”结束本轮并告知用户。此时停止自动重放。用户再次要求操作时按新的指令处理。
- 每轮执行设最大步骤、工具次数、总时长和成本预算；达到上限后结束并解释当前结果。
- 停止播放、取消推理、取消未提交操作分别处理；已经完成的操作如实保留结果。
- 消息历史由服务端维护或严格验证，拒绝伪造的系统消息、工具成功结果和越权会话恢复。
- 用户身份、配置管理凭据和模型密钥不进入模型上下文。文章与工具输出按不可信资料处理。

### 6.4 可选语音

语音选型以一次真实的“开口、识别、调用工具、播报、插话、结束会话”验证为门槛。此前教程使用的 CustomLLM 与托管工具能力存在支持范围差异，接入时重新核对供应商、区域与版本，不能只凭成功聊天确定方案。

实现语音前先确定是由语音平台编排模型与工具，还是自有后端编排并对接语音协议。只能有一个明确的任务执行与授权中心，不能让文字和语音各自维护一套互不一致的工具状态。

必须覆盖：用户主动授权、授权未响应、拒绝或无设备、自动播放受限、外放回声、背景音、中文停顿、连续插话、断网、后台与锁屏恢复。指标使用用户说完到首段有效回答音频的时间，而不是用网络 RTT 代替。

语音状态来自实际链路；有文本生成不等于开始发声。停止时丢弃旧轮次待播音频，释放麦克风和连接；服务端负责闲置回收和最长会话限制。

### 6.5 日志与评测

每次任务记录任务 ID、工具名、耗时、状态、模型与提示词版本、调用量和脱敏错误。默认不保存原始音频与完整敏感聊天正文，调试样本使用单独策略。

评测同时检查最终回答和环境结果。事实问题核对来源；页面操作核对页面状态；写入核对持久化结果；取消核对实际结束情况。同一任务重复运行，模型、提示词或工具变更后执行回归，避免只以一次成功录屏验收。

## 7 模块接口与宿主适配

### 7.1 公共控制接口

以下是能力草案，不是已发布 API。P0 需补齐类型、错误码和时序示例。

| 能力 | 约定 |
| --- | --- |
| 创建与销毁实例 | 挂载到指定容器；销毁后可以再次创建 |
| 加载配置 | 校验版本，拒绝不支持的字段，保留上一有效配置 |
| 设置场景 | 提交房间或阅读上下文及其版本 |
| 请求动作 | 使用稳定动作 ID 或语义目标，并返回执行回执 |
| 显示消息 | 统一消费固定台词、模拟回答与真实 Agent 回复 |
| 控制可见与声音 | 收起、唤回、静音、停止、暂停自主行为 |
| 订阅事件 | 返回取消订阅函数，不能泄漏跨实例监听 |
| 导出或重置个人记录 | 由存储适配器实现，破坏性重置需明确交互 |

### 7.2 事件与命令

事件至少包括用户输入、对话状态变化、回复增量、实际发声变化、动作请求、动作结果、彩蛋发现、配置变化和错误。公共事件只提供状态与执行依据，不暴露模型内部推理。

通用字段使用协议版本、事件 ID 和实例 ID；涉及会话、任务、轮次或动作时，再附相应标识。回复增量包含顺序信息与结束标记。命令包含有效期、目标场景版本、稳定命令 ID 和必要前置条件。

接收端校验版本、目标实例、有效期、授权范围与状态。导航、滚动等动作先返回已接收，宿主在目标页面真正就绪后回送完成回执。丢回执时按第 6.3 节声明的能力查询。实例消失后，新页面恰好显示目标 URL 不能作为旧命令完成的证明。

### 7.3 适配器

| 适配器 | 目的 | 开发阶段替身 |
| --- | --- | --- |
| SceneAdapter | 活动边界、目标、障碍与阅读避让 | 简化房间和阅读样例 |
| HostActions | 导航、章节、主题等宿主操作 | 可记录、延迟、失败的模拟工具 |
| ContentProvider | 公开搜索与文章读取 | 固定内容与可修改 fixture |
| StorageAdapter | 发现记录和个人设置 | 内存、本地与参考服务 |
| ConfigProvider | 读取可运行配置 | 本地 JSON 和参考配置服务 |
| AgentTransport | 输入、回复、状态、取消 | 无网络的模拟 Agent |
| VoiceProvider | 麦克风、转写、播放和停止 | 预置事件与测试音频 |

核心行为逻辑不读取浏览器全局对象。浏览器渲染层与宿主 UI 框架分开；Agent 服务保持服务端边界。适配器必须有契约测试，不能仅因 TypeScript 类型一致就视为兼容。

### 7.4 渲染所有权

独立演示由宠物应用拥有 Canvas、相机和渲染循环。其他开发者可能已经拥有 Three.js 场景，猫进入该场景时必须明确共享方式，不能用覆盖一层透明 Canvas 假定能正确解决遮挡、光照和空间交互。

P1 用一个与博客无关的宿主样例验证共享场景：宿主提供场景挂载点、相机和更新节拍，宠物提供模型节点及更新与销毁接口。明确谁计算位置、谁驱动动画、谁处理拾取、谁释放资产。宿主拥有的相机、渲染器和共享贴图不得被宠物销毁；同一实例不能被两套循环重复更新。

独立 Canvas 和共享场景属于两种渲染适配方式，共用行为核心。首个可复用版本的支持范围在 P1 冻结；若共享场景不进入该版本，就必须在博客接入前补齐验证，且不得宣称已经支持嵌入任意 3D 房间。

## 8 npm 与外部分享要求

### 8.1 包边界

建议以一个宠物包提供独立子入口，例如 core、contracts、web、react、agent。仅按需加载对应功能，导入核心或类型不能初始化渲染、读取麦克风或连接模型服务。React 封装不能成为原生浏览器使用者的必装运行依赖。

具体构建工具、依赖版本、ESM 或兼容格式在 P1 消费实验后决定，锁定支持矩阵并记录。Three.js、React 等宿主可能已有的库，需要评估 peer dependency 与重复打包。包不导出密钥、参考服务内部模块和博客专用代码。

### 8.2 资产授权与分发

代码许可与模型、贴图、动画、音色许可分别核对。采购资产能够商用，不一定允许将源资源随 npm 再分发；授权未明确时不能将其作为默认可分发资产。

资产加载采用清单和可配置基础地址，避免写死个人 OSS、CDN 或相对仓库路径。大资产按需加载，读取进度、失败、重试、超时和替代显示可观察。清单记录资产版本与兼容的动作映射版本。

发布策略在 P1 确定：允许分发的轻量默认资产可随包提供；完整资产也可以单独分发并由使用者显式配置。两种方式都需验证跨域、嵌套部署路径、缓存更新和离线限制。没有合法正式资产时，先交付许可清楚的占位资源，不宣称正式黑猫已完成。

### 8.3 生命周期与兼容

- SSR 环境导入不访问 window、document 或 WebGL；实际挂载在浏览器生命周期执行。
- React 开发模式重复挂载、卸载与重新创建实例后，不重复绑定输入或建立连接。
- 销毁释放动画循环、计时器、事件、观察器、画布、GPU 资源、音频节点、流和订阅；共享资源按引用关系释放。
- 多实例拥有独立状态和存储命名空间；默认实例数量限制与资源共享方式需要文档说明。
- CSS 在自身容器内生效，明确层级、指针事件和主题变量，不能修改宿主 body 或全局样式。
- 支持尺寸变化、缩放、触摸、键盘和减少动态效果；WebGL 不可用或上下文丢失时提供替代显示与恢复入口。
- 从纯净目录安装打包产物验证，不能只通过仓库内部源码别名证明可用。

### 8.4 发布产物

发布候选应包含 API 与类型文档、安装示例、无 Agent 示例、自接 Agent 示例、SSR 示例、资产与许可证说明、卸载与错误处理、支持矩阵、版本迁移说明与变更记录。

包版本、配置版本、事件协议版本、资产版本分别管理并声明兼容关系。破坏性变更需迁移说明。发布前先检查打包文件和在干净项目安装压缩包；npm 发布、公开演示部署、开源仓库公开属于后续单独安排的发布动作，本计划不执行。

## 9 独立验证环境

| 环境 | 必须具备的能力 |
| --- | --- |
| 宠物实验室 | 切换动作与场景、配置点击参数、固定随机种子、查看状态与动作队列、模拟加载失败 |
| 配置与记录控制台 | 编辑预览、校验报错、启用和回退、记录查询与重置、未授权访问测试 |
| Agent 实验室 | 查看输入、来源、工具参数、结果、耗时和预算，注入工具错误与模拟页面回执 |
| 完整独立演示 | 宠物与 Agent 同时运行，提供示例房间、阅读页面、语音开关和统一停止控制 |
| 外部消费项目 | 在包外安装构建产物，覆盖普通浏览器、React 与 SSR 宿主 |

模拟模式是长期保留的能力。任何开发者在没有供应商账号和密钥时，都能检查猫的表现与协议。真实模式单独配置服务端凭据，不能通过构建变量把秘密打进前端包。

## 10 阶段任务与退出条件

阶段编号用于归类，实际顺序以第 10.2 节的任务前置为准。D05 定义最小共用协议，E01–E03 提供普通浏览器即可运行的样例和故障注入。文字 Agent 在这条公共路径上开发。房间、美术与渲染接在宠物分支，语音接在 Agent 的可选分支。

验收设置三个独立里程碑：宠物与模拟 Agent 通过后可形成宠物包候选；Agent 在调试页通过后形成 Agent 模块候选；两者联调通过后形成完整伴侣演示。语音的目标体验保留，是否进入首个独立交付在 P0 冻结。若首个交付只含文字，语音实验和实现不得阻塞宠物、文字 Agent 或宠物包；文档也不得宣称已经提供完整语音能力。

| 阶段 | 任务 | 交付物 | 退出条件与依赖 |
| --- | --- | --- | --- |
| P0 产品和接口冻结 | 完整场景、性格与视觉方向、动作清单、点击规则、阅读规则、配置字段、事件与适配器 | 体验规格、状态表、接口草案、资产需求、验收用例 | 关键决策有记录；核心场景和失败路径完整；无需代码即可说明预期结果 |
| P1 风险验证与技术基线 | 骨骼动作链、渲染预算、SSR 导入、包外消费、资产加载；Agent 侧另验证模型工具与语音支持 | 小实验结果、技术决策、支持矩阵与预算 | 高风险项可行或有明确降级方案；P0 后方可开始，当前不执行 |
| P2 独立工程与模拟依赖 | 建公共骨架、示例文章、模拟宿主、事件回放，再建宠物专用场景 | 公共调试入口与独立宠物实验室 | 公共层凭 D05 即可启动。宠物实验室另接渲染验证，普通浏览器调试页可单独加载 |
| P3 宠物主体 | 资产制作或采购、全动作审片、行为与移动、阅读、点击与彩蛋 | C07 正式资产交接包、宠物独立演示 | 视觉按两种镜头验收，行为按固定输入回放。工程验证可先用占位猫，正式验收使用审片通过的资产 |
| P4 配置与记录 | 控制台、参考服务、存储适配器、版本与迁移、身份与管理权限 | 配置发布回退、发现记录完整流程 | 无效配置不破坏运行；重复写入不重复发现；刷新恢复符合模式；依赖 P2 与 P3 规则 |
| P5 Agent 主体 | 文字、内容提供器、工具、权限、取消、预算、回执、可选语音 | Agent 独立演示与评测集 | 真实工具链、对抗与故障用例通过；纳入当前交付的语音另通过真实链路验收；依赖 P2 的契约与示例内容 |
| P6 独立集成 | 接入真实 Agent 到宠物；配置、记录、阅读和停止联调，按版本范围加入语音 | 完整独立演示、回归与性能报告 | 状态一致、无旧消息干扰；离线/真实模式均通过；依赖 P3 P4 P5 对应能力 |
| P7 可复用交付 | 正式资产性能测量、包外安装、文档、许可与兼容检查 | 同一版本的性能报告、候选压缩包与外部示例 | N00 使用模拟 Agent 完成独立宠物验收，N01 核对同一产物的包外消费。真实 Agent 的联调开销另在 P6 验证 |
| P8 博客适配 | 实现博客场景、公开内容、路由和记录适配器 | 博客集成变更与端到端结果 | 要接入的能力已在独立环境与包外验收；完整伴侣接入需 P6 P7 通过；用户明确进入接入阶段 |

每项 P1 实验只约束使用该能力的分支。动作样片未通过则调整资产制作方案，语音工具不兼容则调整语音选型。公共工程和其他已满足前置的分支可继续推进。

### 10.1 开发任务的统一格式

每个任务至少包含：任务 ID、所属模块、输入与前置依赖、实现范围、公共接口影响、交付文件或资产、验收用例、失败或回退方式。涉及素材、API、权限和数据迁移的任务必须分别标出依赖。

任务状态使用待开始、进行中、待验收、已通过、需调整。未经验收不能仅凭“代码已写完”进入已通过。视觉、文案和陪伴感需要用户确认的样例；参数校验、状态、操作结果和资源释放使用自动化或可复现检查。

### 10.2 可分配的任务清单

任务编号与验收条件作为执行基线，实际状态记入独立工程进度。用户已授权推进，可逆的协议和占位原型先行验证。需要用户决定的视觉、采购与供应商事项记录到待确认清单，正式验收仍依本表完成。

| 任务 | 阶段 | 前置 | 具体交付 | 主要验收依据 |
| --- | --- | --- | --- | --- |

## 12 性能与运行预算

P0 确定设备、网络、测量方法与拟定门槛。P1 用样片确定宠物预算。N00 用正式资产和模拟 Agent 在目标设备上对照预算验收，记录包版本、资产清单、设备、网络、观测区间与原始结果。N01 只接收通过该检查的产物。I02 在相同条件下记录接入真实文字或语音增加的开销。

| 项目 | 测量方式 | 设定与复测节点 |
| --- | --- | --- |
| 包体积 | 分别记录核心、渲染、React、Agent 入口压缩前后体积 | P1 P7 |
| 资产体积 | 模型、贴图、动画、额外解码器及首次实际传输量 | P1 定预算，N00 测正式资源 |
| 首次可交互 | 冷缓存和热缓存分别计时，标明网络与设备 | P1 定预算，N00 测正式资源 |
| 渲染性能 | 房间、阅读、动作与对话同时进行时的帧时间和内存 | P1 定预算，N00 验收，I02 比较增量 |
| 释放资源 | 重复挂载卸载前后的监听、连接、GPU 与内存趋势 | P2 建测量方法，N00 验收，I02 复测真实连接 |
| 文字响应 | 首个有效内容、完整任务耗时、工具调用分段耗时 | P5 |
| 语音响应 | 用户结束发言到首段有效回答音频、误抢话和漏打断 | P1 P5 |
| 费用 | 每轮调用量、语音分钟、每会话和每日预算、超额处理 | P5 |

优先保证宠物不拖累宿主阅读与交互。房间模式和阅读模式可以采用不同渲染质量；资源与语音按需启用。低端设备的降级方式与支持范围在正式开发前明确，避免无依据承诺所有设备保持相同效果。

## 13 风险与处理门槛

| 风险 | 提前处理 | 无法满足时的调整 |
| --- | --- | --- |
| 模型与动作来源不允许再分发 | 采购或制作前核查代码、模型、动画各自许可 | 更换或自行制作合法资产；保留自带资产入口 |
| 正式猫观感和绑定不理想 | 先验一条完整动作链、两种镜头与暗色背景 | 调整模型和骨骼，推迟扩充动作 |
| 语音供应商与工具链不兼容 | 真实跑一次语音加工具闭环 | 更换支持组合或调整服务端编排，保留文字版本 |
| 状态相互覆盖 | 单独管理身体、场景、对话、任务并定义优先级 | 缩减同时动作，优先保证明确的恢复路径 |
| 隐藏内容被 Agent 剧透 | 信息分级与 fixture 注入测试 | 缩小给 Agent 的内容范围 |
| 写操作重试或取消造成不一致 | 稳定 ID、回执、状态查询与故障注入 | 未解决前只开放查询与可控界面操作 |
| 记忆或发现记录串用户 | 各层归属、缓存隔离与并发测试 | 默认本地记录，待身份方案通过后开放云同步 |
| 包只能在当前项目使用 | 尽早打包并从纯净目录消费 | 先修正依赖、入口和资源路径，再接博客 |
| 配置修改导致运行中断 | Schema 校验、安全点更新与版本回退 | 禁止不兼容热更新，采用明确重载 |
| 范围逐渐扩大 | 每项新增功能补影响、依赖与验收 | 调整版本范围，重新评估计划 |

| 技术与支持矩阵 | TypeScript 核心、浏览器渲染、React 适配作为候选，版本由消费实验决定 | P1 |
| npm 与开源方式 | 代码、资产与服务分开考虑许可证，包名和 scope 另查 | P1 P7 |
| 时间与投入 | 先估资产制作、服务接入、跨浏览器验证，再按任务估算 | P0 P1 |

排期按分支估算。共用协议和模拟宿主就绪后，文字 Agent 可沿 A01–A03 独立验收。宠物线在正式资产交接和行为开发汇合后进入 N00–N02。完整伴侣另行联调，语音计入选用该能力的版本。博客接入排在所选能力的独立验收之后。

## 15 完成定义与博客接入条件

宠物交付以正式资产交接、宠物实验室、配置与记录、模拟 Agent、包外性能及安装通过为条件。文字 Agent 可在普通浏览器调试页单独完成公开内容查询、模拟导航、回执确认、取消和权限验收。完整伴侣在独立演示中联调，语音按冻结范围单独登记结果。

宠物交付附 C07 的资产与许可清单、N00 的性能结果和 N01 的安装验证。Agent 交付附模型与工具支持矩阵、授权与故障用例的执行记录。各自列明实测版本、运行条件和遗留问题，完整伴侣再附 I02 的联调报告。

博客接入前保留独立工程与演示。博客只新增适配代码，提供场景、公开内容、路由、阅读状态与所选存储。已有博客管理 MCP 不进入访客 Agent。若接入需要改动宠物核心，先判断是公共能力缺失还是博客细节侵入，公共修正须在独立演示中回归。

接入后的验收补充：房间和文章切换、浏览器前进后退、阅读位置恢复、主题和语言、已有页面性能、浮层避让、关闭功能及回退。宿主应能通过一个明确开关停止加载宠物和 Agent，恢复原有博客使用。
