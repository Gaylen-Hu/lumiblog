# 小灰网页运行时

由独立猫工程的 `apps/toon-cat/website-cat.js` 及其动作、模型、聊天模块迁入，并增加网站书房的导航适配。模型、骨骼、贴图、面部和动作沿用已制作的小灰；没有重造一只简化猫，也不依赖开发机上的另一个目录。

网页端入口为 `mountWebsiteCat(options)`，异步创建一个有透明背景的陪伴层。默认聊天入口 `/api/companion` 使用网站现有后端。代码由 Next 延迟加载，GLB 和贴图位于 `/companion/v1/`。猫头与身体贴图并行下载。

默认猫头下载为 2,163,937 字节。Meshopt 对独立顶点和索引做无损编码，保留表情、虹膜和顶点顺序。毛色贴图为 1024 × 512，眼部法线图为 512 × 512。若浏览器限制 WebAssembly，则使用已有的 3,113,791 字节兼容模型。缺少原生 gzip 解压能力时按需加载 JavaScript 解压器。

替换原始头模后，在博客前端目录运行 `node scripts/build-companion-head.mjs`，将输出的带内容哈希的文件名更新到 `native-head.js`。此前的文件名可以继续供已打开的旧页面使用。

## 宿主接口

- `setRoomStage(stage|null)` 把同一只猫移入网站房间或移回阅读陪伴层。房间使用现有 renderer、camera 和动画时钟；切换保留聊天与房间落点，不再独立绘制右下角猫。
- `setReading(bool)` 由网站阅读状态自动切换安静陪读，离开文章后恢复房间活动；没有手动陪读按钮，不改变用户隐藏偏好。
- `setHidden(bool)` 收起猫，仅保留小恢复按钮；`onVisibilityChange(visible)` 通知宿主保存偏好。
- `setSuspended(bool)` 为页面隐藏、其他模态等临时状态暂停渲染和交互、终止回复、关闭聊天，不通知隐藏偏好变化。
- `setReducedMotion(bool)` 禁用指针视线跟随，让待机姿态静止，只推进明确触发的动作和短暂抚摸反馈，动作后恢复静止。渲染上限降至 15 FPS；通常桌面上限 30 FPS、移动端上限 24 FPS。
- `openChat()` 从宿主入口打开底部轻输入条；猫本身轻点为抚摸、长按约 550 ms 聊天，键盘 Enter 聊天、空格抚摸。
- `destroy()` 中止 GLB 下载及聊天，销毁动画控制器、DOM、监听、观察器和 GPU 资源，可重复调用。
- `signal` 可取消正在进行的挂载。GLB 下载可取消；解码期间收到取消则在解码完成后释放模型，不把它加回页面。
- `website` 是可选的网站助手适配器，提供当前公开文章上下文、本站能力白名单、房间操作及草稿准备；未传入时不授予任何网站操作能力。完整类型见 `website-cat.d.ts`。

猫的渲染和聊天气泡均挂到 `options.container`，使用 Shadow DOM 隔离样式，并遵守宿主的层叠上下文。`onChatOpenChange(open)` 用于协调宿主键盘快捷键，销毁时恢复 false。英语页面目前仅猫控制按钮和画布标签本地化，聊天内容保留小灰现有中文人格。

## 功能边界

网站书房使用 `motion/study-navigation.js` 的家具坐标、旋转障碍和安全落点；`room-stage.ts` 协调场景注册、绘制与可见性。猫的原始尺寸通过父节点统一放大 1.35 倍，位置与步幅始终使用猫的局部单位。

房间中点击无交互的空地可走动，点击桌椅的裸露面可跳到安全位置；原书本、日记和灯等交互优先，镜头拖动不下达移动指令。导航避开家具，桌椅互换先回地面。默认每 40–70 秒选择一个可达的散步点，可在挂载时用 `wanderInterval` 调整；阅读、减少动态和用户互动期间不会主动漫游。

房间能力包含 `ground/chair/table/user`，角落阅读层只开放原地姿态，发送 `moves: []`。AI 动作与手动动作共用同一个执行器和结果回执，不能在文章页执行房间跳跃。“坐下”“走走”“上桌子”“上椅子”“回地面”等明确口令可在本地处理，自由聊天仍需要已启用的博客后端。

压缩猫头加四张外部毛色图片的下载量约为 3.52 MB。图片与模型在浏览器缓存，程序引用固定本地资源，不引用公网图床。`motion/` 保留原姿态驱动依赖；`agent/` 保留会话恢复、流式传输、真实动作回执及取消协议。开发来源记录仅用于维护追溯，不表示新增或扩大素材使用许可。

## 网站助手适配

本站的 `../website-assistant.ts` 将下列接口注入运行时。文章、灯光和留言表单留在网站层，猫本身不读取任意网页内容，也不持有网站管理员凭据：

| 接口 | 用途 |
| --- | --- |
| `getCapabilities()` | 返回当前可用的 `site` 和 `drafts` 列表；每次执行重新检查 |
| `getContext()` | 当前文章标识、正文选区及当前访客的灯/窗帘状态 |
| `subscribeContext(listener)` | 页面变化时通知运行时，切换文章取消旧回答与旧计划 |
| `execute(value)` | 通过现有宿主控制方法执行固定房间操作并返回真实结果 |
| `prepareDraft(kind,text)` | 只生成待用户查看的内存草稿，不提交信件或评论 |

`../website-context.ts` 由 `MagazineArticle` 注册公开文章元数据，并按真实 URL 过滤仍挂在翻页动画里的旧文章。浏览器只发送 `slug / locale / title`、可选正文选区及小节提示，不发送全文。选区最多 1000 个 JavaScript 字符单位，只取当前 `#post-body`，输入框与其他页面内容不参与。先选中正文，再长按小灰，输入“解释这段”即可；询问“这篇文章讲了什么”可使用当前文章上下文。没有为这些操作增加常驻的大按钮。

后端按 `slug / locale` 从本站已发布文章库取正文，不抓取任意 URL。正文片段总量最多 16000 字符，长文需要截断时会披露；后段选区能匹配原文时可带上附近片段。`context` 流事件携带可信来源，聊天记录显示文章链接和“部分正文”标识。缺失文章必须明确说明；选文不能匹配原文时作为用户引用。文章资料不能授权房间操作或寄信，这不是全站检索能力。

`site` 固定为 7 项：`ceiling_on`、`ceiling_off`、`lamp_on`、`lamp_off`、`lamp_auto`、`curtains_open`、`curtains_close`。它们只修改当前访客房间，沿用网站原有的顶灯、台灯自动模式和窗帘动画。“开灯”“关灯”“打开台灯”“关闭台灯”“台灯自动”“拉开窗帘”“拉上窗帘”等精确口令无需模型连接。房间未注册或不可用时能力为空；引用、否定、文章中的文字不会通过精确口令入口执行。

`draft` 计划使用 `{kind:'draft',value:'letter'|'comment',text:'…'}`，纯文本最多 3000 字符。成功回执仅表示草稿准备完成，尚未发送。`../website-drafts.tsx` 显示轻提示“查看留言草稿”，用户点开后可编辑：

- 写信由用户继续到原有信纸，填写昵称和邮箱，并最终点击“封缄寄出”；默认私密。往返保留修改，已有待审稿或手写信不能被静默覆盖。
- 待审稿的前端编辑状态只在内存保留，刷新不保留，不进入 URL 或本地持久存储。用户后续编辑和信纸中的联系方式不自动回传给模型；模型已生成的原稿仍属于已有对话。寄送中/结果未知时保留原提交包等待确认；送达凭条交给原有 `LetterDeliveryContext`，不提供给模型。
- 评论只在当前文章已有 Giscus 入口时开放，用户自行复制、定位评论区、登录和提交。运行时不会向 Giscus 发消息，也没有自动发布或后台审核能力。

移植到其他网站时可不传 `website`，或替换为该网站的适配器。网站层继续管理权限、文章标识和确认界面；若要把猫放进另一个 3D 房间，还要替换场景挂接和导航坐标。当前没有发布通用 npm 包，不能将本站家具坐标视为任意网站的默认配置。

## 联调与上线边界

开发环境由前端显式设置 `COMPANION_PREVIEW_API=http://127.0.0.1:<现有后端端口>`，默认常用端口为 3000；Next 开发预览维持回环地址绑定。现有 Nest 后端通过 `CAT_COMPANION_ENABLED=true` 启用，DeepSeek 等模型配置只放后端私密配置。文章解读需要后端公共文章库可用。实际寄信另需原有 `LETTERS_PREVIEW_API`，准备草稿本身不依赖寄信接口；Giscus 沿用网站已有公开配置。

生产使用同源 `/api/companion/` 代理到现有 Nest `/v1/public/companion/`，校验 HTTPS Origin、签名 Cookie 和可信代理令牌；开发 Next 代理不能代替生产配置。生产仍为单实例，并需持久预算目录，发布前更换开发临时模型密钥。完整路由、配置字段和部署验收项见仓库 `docs/companion-backend-integration.md`。

这些能力已落入本地代码；文档不表示已经部署或真实模型端到端全部验收通过。新增测试与构建结果以本轮最终验收汇总为准。语音、全站知识检索和跨会话长期记忆尚未接入。
